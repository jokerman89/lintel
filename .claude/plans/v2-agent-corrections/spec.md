## Method and compatibility

Agent markdown is the shipped implementation. Tighten its actual procedure and
report obligations, not only its title or recommendation. Reuse existing methods
and state where delivered behavior already satisfies a clause. A named specialist
is expertise to consult or hand off when authorized, not an automatic actor launch.

All names, tools, model/memory compatibility fields, discovery support and required
notices stay unchanged. Only the two insufficient trigger descriptions may be
clarified. No role deletion/merging or policy/governance change is authorized.

Security/privacy work is defensive static analysis of supplied source, flow,
manifest or report representations. No payload, exploitation, live request,
scanner, credential validation or tool-abuse execution is added. Fixtures use
inert structured data; their results prove source/report contracts and arithmetic,
not model detection efficacy or live-host behavior.

## Verification and exclusions

Use `tests/behavior/v2-agent-methods.py` with at most one matching shell wrapper.
Pair source obligations with discriminating report-shaped fixtures and mutations
that would otherwise overclaim PASS. Preserve the existing shared behavior harness
and the other owner's source scope unchanged. Retain initial failures and exact
command/source/log identities. Run no whole suite or hosted dispatch.

Excluded portions remain explicit: SchemaArchitect/DataPipelineDesigner absorption,
role/portfolio retirement, new defaults or packs, unrelated review-skill routing,
tool permissions, active testing and live environment changes. Generated adapters,
catalog/wiki/showcase, versions, changelog, shared memory and todo are coordinator
outputs, not lane edits. Expected native drift is not a native PASS.

Master assigns the independent reviewer after the frozen implementation handoff.
This map approves work, not release. Completion here never means all V2 is done.
