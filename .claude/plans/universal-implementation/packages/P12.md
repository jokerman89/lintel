# P12 - Artifact-specific document production

**Authority:** A15, CP-08/09/18 and AG-13; inventory of document skills/roles.
**Prerequisites:** P05/P06/P07/P08/P09 and P11 shared design schema.

## Ownership and value

Own `generate`, `generate-outline`, `generate-write`, `generate-ppt`, `generate-word`,
`generate-pdf`, `generate-xlsx`, `generate-visio`, `generate-qa`, `make-pdf`,
`document-generate`; format methods/templates/helpers and doc-gen agents after P09;
focused tests and P12.md. P11 owns shared web/design; consume rather than fork its schema.

Preserve facts, source provenance, complete argumentation, editable outputs where
promised, narrative planning, specialist format expertise and all original entry points.
No universal 40-word section truncation or fixed language convention. Shared factual
briefs are not a slide-sized universal output schema.

## Leaves and checks

| Leaf | Dependency | Observable acceptance |
|---|---|---|
| A15.1 | Predecessor contracts | Shared source claims feed format-specific composition/QA with work/profile identity |
| A15.2 | A15.1 | A long technical explanation retains reasoning and citations across section/page boundaries |
| A15.3 | A15.2 | Actual supported Word/slide adapter produces editable artifact and rendered inspection evidence |
| A15.4 | A15.3 | PDF/XLSX/Visio each has concrete writer/renderer/recalculation/reopen procedure, implemented status only where verified |

Split rendering/validation leaves by format into stable sub-IDs before starting.
Use actual installed/native canvas/office/PDF/browser tools when available and inspect
their schemas first. Missing tool/library must be observed before installation; any
new validation dependency stays task-local and declared. No personal Office documents,
customer data, macro execution or external upload.

Add `tests/integration/document-format-pipeline.sh` (support modules allowed). Use a
small synthetic brief that includes a long explanation, table, links and an evidence
claim; slides additionally need overflow/asset checks, XLSX real recalculation and
formula/cache integrity, PDF page/text fidelity, Visio connectors/labels/reopen/editability.
A parse-only ZIP/XML test does not prove rendered layout or true application editability.

Preserve planned valuable formats with a working-code path and specific activation/
environment test, not an indefinite unsupported label. Where real render/reopen capability
cannot be obtained within authorized environment, state the exact remaining gate and
retain staged maturity instead of claiming the format fully ready. Keep that acceptance
leaf open if its required observation is missing.

Commit locally, report exact files/revisions, actual render/recalc/inspection commands
or native actions, output artifacts, retained content evidence and precise limitations.
Independent spec/quality review follows; no product capability deletion or publication.
