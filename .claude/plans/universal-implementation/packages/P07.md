# P07 - Stable effective profiles and compatibility

**Authority:** A07 and A20.3/4 in plan.md/spec.md; explicit operator demand that required
policy cannot become neutral success. **Inputs:** P06 operations and P05 outcome contracts,
audit RT-03/04/10, WF-06, CP-07/12, AG-05; current pack/adapter source and tests.

## Accepted behavior boundary

Preserve whole-top-level-block inheritance, explicit null/false/list semantics, extension
packs and source/target separation. Introduce the stricter required-profile behavior with
reserved ADR-0029 and directly related docs/tests, not by silently changing an old ADR.
Neutral first use with no requested organizational profile remains valid.

A required profile is declared outside the potentially broken manifest so load failure
cannot erase the requirement. Prefer a small optional repo data declaration under
`.claude/` plus explicit invocation selection over another configuration service.
Document precedence: repository-required constraints cannot be replaced by a user-global
preference; explicit approved source/target paths remain honored. Legacy optional
preference fallback may remain diagnostic, but never constitutes successful activation
of a required named profile. An invalid bundled neutral baseline returns an actual error.

Pin effective source/name/version/ancestry/content to the selected work/session context.
Tool-shell PID is not durable session identity. Child handoff and cold restart carry/
verify the same profile reference. Detect active-pointer and manifest/ancestor changes,
including same-mtime content changes; do not silently switch policy mid-work. Provide
explicit rebind/replan procedure preserving old evidence.

Store only approved non-secret identity/provenance in reviewed artifacts. Runtime copies
stay within existing gitignored `.claude/runtime/` or explicitly selected LINTEL_HOME.
Do not read or activate the operator's real private pack while developing tests.

## Profile history teardown diagnosis release (2026-09-24)

Three independent test runs on Windows ended with a `TemporaryDirectory` cleanup error,
WinError 145 ("directory is not empty"), under a synthetic home's
`.lintel/sessions/profiles/<hash>/history`:

- SAME9db's A13.b retry `b02`, in `test_frozen_zone_and_session_digest_records`;
- its full run `b03`, in the same test and in
  `test_writer_path_equals_reader_path_in_every_scope`;
- once, the same class in P09's installed-consumer test (`…\sessions\profiles\<hash>`).

In each case the history directory still holds one `1-<digest>.json` file of about
22.4 KB, the generation-1 binding record that `_retain_record` writes. The files are:

- `b02`: `1-9a01ed56…json`, 22,438 bytes;
- `b03`: `1-3cd7624d…json`, 22,438 bytes, SHA-256 `2d7bed29…fde9bf7d`;
- `b03`: `1-00376c0b…json`, 22,506 bytes, SHA-256 `96d36867…f091b7b5`.

The file was written at the moment of the failure, and it still exists afterwards, so
it was not a pending delete. The failing tests run their hooks synchronously, and no
hook, `lib` or `bin` code starts detached processes. The cause is not established: the
host's scanner or a late writer are both possible.

  history file at teardown. Look in particular at the lock, retention and replacement
  protocol around `_retain_record`.
- Change only `lib/profile_context.py`, owned profile tests and directly related docs,
  and only if the evidence shows a product cause. Otherwise, report the environmental
  cause with evidence and change nothing.
- Work test-first, with a discriminating regression when a product cause is found.
- Freeze for SAME `a7d78944`, and send the handoff to the coordinator in parallel. Any
