**Authority:** A02/A03 in plan.md/spec.md; ADR-0028.
**Inputs:** P04 historical merge checkpoint; audit WF-01/02, AG-03/04/11/15,
CP-08 and RU-01, current `bin/li-review-*`, relevant tests.
**Prerequisite:** P04 merge checkpoint integrated and stable. P07 required-profile
semantics are agreed in P07's card; do not wait for its code to fix review readers.

## Ownership and shared interface

Own `bin/li-review-log`, `bin/li-review-read`, new minimal `lib/review_contract.py`,
`lib/review-schema.json` and `bin/li-review-evidence.py` if needed; review/control
skills `review`, `code-review`, `ship`, `qa`, `qa-only`, `compliance-gate`;
the mandatory-control portions only of affected compliance roles and
`agents/frontend/DesignSystemAuditor.md`; the time-only reuse/empty-test portions of
`agents/engineering/CodeReviewer.md` and `TestRunner.md`; the shared-reader warning
path in `hooks/shared/no-merge-without-review/run.sh` and its HOOK.md; focused tests.
That hook remains advisory/opt-in and is not activated. Read scoped instructions
before editing. Do not alter Swarm/Brief Forge, host/profile/work-map helpers,
generated outputs, shared plan/memory or the whole specialist role corpus.
Report to `reports/P05.md`; list downstream domain/design/Swarm consumers.

Define one strict, versioned JSON result/evidence contract in the shared implementation.
Preserve existing shell entry points as compatible adapters; malformed JSON must not be
accepted by a regex fallback. Historic records remain inspectable, not automatically
clearance. Preserve the existing source/target separation and local audit ownership.

The shared Python API should expose pure validation/control evaluation and snapshot
identity operations reusable by Swarming. Settle exact public function/CLI signatures
in the report before dependent code consumes them; send MasterSession the interface
early. Core fields: schema version, work-map reference, package/leaf IDs, acceptance
digest, profile identity when supplied, attempt/actor provenance, base/head, explicit
selection manifest/result digest, controls and evidence links. Do not invent an external
review identity: retain declarations versus host-correlated observation distinctly.

Add executable `tests/unit/review-evidence.sh` and `tests/unit/mandatory-controls.sh`

required evidence rather than weakening strict behavior. Include malformed/duplicate

new files. Evidence record self-exclusion must not hide arbitrary plan/config changes.

Use isolated fixture repos and homes; no global logs, private profiles, real PR or network.
No ordinary question is needed for the already-approved fail-closed acceptance behavior.

## Preservation and report

Retain human-readable review reports, useful advisory design scoring, raw historical
audit inspection, native shell command entry points and legitimate unmodified-result reuse.
Do not claim checksum equality authenticates a human or host identity by itself.

Commit locally. Report exact revision, schema/API, commands/results mapped to every leaf,
preserved use cases, intentional legacy compatibility behavior and consumer migration needs.
Stop for independent spec then quality review; no self-approval or remote mutation.
