## QUALITY (eligible after SPEC PASS)

The fix removes the order dependence at its cause: the guard now measures what the
adapter actually writes, rather than whatever happens to be in the checkout. It keeps
the limit and message, and it cannot drift from the adapter, because the test already
treats `generate()` as ground truth in `installed()` (`:207`). Relaxing this preflight does not
weaken the real budget: `command()` still checks every fixture path against 220 after
each child call (`:159-160`). The regression tests both sides, the ignored path that must not count
and the bundled path that must still refuse, and it never writes the real checkout.

Observations, not findings:

- `generate()` now runs once per `setUp`, and the regression calls it four times. On this
  loaded host one call takes about 5–10 s, adding roughly a minute to an entry of about
  30 minutes. This is input for N1's CI budget, not a defect. The old guard's full
  `rglob` of the checkout was itself proportional to the ignored evidence.
- `setUp` still snapshots every file under the source root, ignored evidence included,
  to assert it is unchanged. That behavior predates this unit and passed with the planted
  evidence. Evidence paths beyond the host's 260-character limit could still make that
  read fail, but no current test is known to write such paths into the checkout.
- The regression plants its 206-character synthetic paths without a following
  `command()`, so the per-command 220 check does not see them. They are within budget.
