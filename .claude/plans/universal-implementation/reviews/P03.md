### F1: restore authorization is not consumed per completed file

The journal records only the whole operation's `in-progress`/`complete` state. On resume,
every non-original file can again be authorized by the old result receipt; there is no
record distinguishing files already restored from files not yet processed.

Reproduced with two owned files, both initially `feature=off`, then changed by the
operation to `feature=on` and bound to its receipt. Interrupt restore before its second
file: A is now restored to `off`, B remains `on`, and the journal is `in-progress`.
After the failed call has returned, a user re-enables A to `on`. Rerunning restore
accepts the old receipt, writes A back to `off`, and returns `state: complete` with
both files in `changed`. The later user edit is lost.

This requires neither concurrent writers nor a checksum collision. Reapplying a setting
or saving an editor buffer can reproduce the original operation's post-image exactly.
Both calls run against a quiescent target. The defect is missing per-file recovery
progress, not the disclosed lack of a whole-tree transaction. By contrast, a distinct
later edit to the pending B file correctly conflicts and is preserved.

**Repair expectation:** consume rollback authority per file through a recoverable
progress journal. A completed path must be checked against its restored state, not
reauthorized against the original operation receipt. Handle an ambiguous interrupted
transition explicitly rather than silently assuming ownership. Add this exact
interruption/re-edit/resume case, alongside the existing ordinary resume case.
This blocks A01.2.c/A01.3 and the in-place recovery path used by A01.4.b.

### F2: the helper's detached sentinel fails its new branch validation

`_context_branch` explicitly returns `HEAD` for a detached committed checkout
(`bin\_context.sh:54-55`), but `git check-ref-format --branch HEAD` rejects that name.
Consequently `context_save_path`, `context_list` and normal latest/owned-checkpoint
discovery fail. The skill still promises detached `HEAD` support at
`skills\context-save\SKILL.md:144`.

The same synthetic detached repository was exercised with the base version of
`bin\_context.sh` plus `lib\paths.sh`, then with the result helper: base save/write/latest
returned 0; result returned 1 with `Invalid checkpoint branch; refusing path traversal.`
Ordinary branches, plain directories and unborn branches passing do not cover this
case. It also affects the detached trial workflow now recommended by the roles.

**Repair expectation:** preserve the explicit safe detached-checkout namespace without
weakening validation of user-supplied branch/path data. Add detached save, list, latest
and owned historical-read regression cases. A11.1 is not preserved in full.

### F3: cooling compares spellings instead of Windows file identity

Cooling stores the normalized separator spelling but not a canonical file identity.
Selection compares relative strings and case-sensitive patterns. On native Windows,
`DOCS/NOTES.md` and `docs/notes.md` were verified to read the same existing file.
Cooling `DOCS/NOTES.md` succeeds, yet a subsequent `docs/*.md` selection includes
`docs/notes.md` and reads its bytes. Reversing the case at a later literal selection
has the same underlying problem.

**Repair expectation:** make literal exclusions and applicable glob matching consistent
with the supported filesystem's path identity, while preserving case-sensitive
filesystem behavior. Cover differently cased literal and glob consumers on Windows.
The zero-token/zero-disk-reclamation reporting is correct; the promised future-read
exclusion is not, so A11.4 fails.

### F4: a file prefix short-circuits the complete glob

For an existing regular file `notes.md`, selecting `--glob 'notes.md/*.md'` returns
that file with status `selected`. `_glob_files` finds the literal prefix, notices it is
a file and returns it without testing the remaining pattern. No file can be a child
of that regular file, and `notes.md` does not match the requested pattern.

**Repair expectation:** return a literal-prefix file only if it matches the entire
selector; otherwise return an unmatched/empty result or an explicit invalid-selection
error. Add both the helper and CLI non-success assertion. Containment still holds,
but the source set is outside the requested glob, violating A01.1.b.

## Integration debt and limitations, not additional P03 defects

- **Coordinator-owned catalog drift:** the changed source descriptions make the generated
  catalog stale. Its failing check is real, but regeneration is outside this writer's
  ownership and is not included in the four product findings.
- **P08 historical-capacity test reconciliation:** the two passing string suites still
  announce a 500k/750k default-capacity mechanism by finding historical example text.
  They do not demonstrate capacity, enforcement or synthetic-token exemption. P03's
  helper observations, not those messages, support the bounded A11.2/A11.3 passes.
- **Host/browser/installer boundaries:** tests do not supply a real single-hop HTTP/browser
  adapter, telemetry/pricing, full installer ownership integration, live migration or
  host enforcement. Those missing surfaces are explicitly disclosed, not replaced with
  invented observations. P06/P07/P08/P09/P10/P11 and integrated acceptance retain their
  assigned follow-up work.
- **Recovery boundary:** snapshots cover regular files and recorded modes, not arbitrary
  metadata, databases or services. No hard machine-crash durability or cross-process
  transaction is established. Quiescent/isolated targets and manual stale-lock recovery
  remain disclosed prerequisites; neither excuses the sequential F1 reproducer.
- **Review boundary:** no full suite, CI, remote comparison, consumer install, live
  client/model acceptance or private-pack compliance run occurred. The bundled neutral
  pack declares advisory mode and no hooks; no personal pack was inspected or activated.
  The seven additional passing checks and repeated CLI rounds do not establish universal
  safety or compensate for the four failed requirements.
