### F01 - P2: agent aliases bypass cross-record collision checks

**Location:** `bin/li-catalog.py:279-284` (alias handling), with matching at `287-299`.
**Confidence:** 10/10. **Kind:** new first-unit specification failure.

Agent aliases are converted to output objects without the cross-record ownership checks
used for skills; canonical-name uniqueness does not validate aliases.

Reproduced with `Alpha` declaring `deprecated_aliases: [Beta]` and a canonical `Beta`:
`--json --kind=agent --name=Beta` returns exit 0, empty stderr and `matched: 2`.
`--kind=all` has the same problem. Giving the two agents `Shared` and `shared` aliases also
returns two exact-name matches. An unmatched query over the conflicting inventory still
returns exit 0 with `matched: 0`, so filtering hides the invalidity.

These are already-consumed fields, not future capability metadata. Duplicate canonical
agent names correctly refuse; query fixture hashes remain unchanged. This violates the
current dispatch and `skills/catalog/references/metadata.md:98-101,117-121`: reject
collisions/ambiguity before output and before filtering.

**Fix:** validate case-insensitive agent alias ownership and alias/name collisions before
filtering; preserve skill/agent namespaces and reuse existing collision policy. Cover
alias/name, alias/alias, case variants, `agent`/`all` and unmatched-query cases.

**Evidence:** `06-adversarial-controls.stderr`; `confirm-agent-agent-exact`,
`confirm-agent-agent-empty`, `confirm-agent-all-exact`, `confirm-alias-alias` and
`confirm-duplicate-agent-name-control` command/output/exit/seal records.

**Location:** `bin/li-catalog.py:88-100`, reaching the write at `343-345`.
**Confidence:** 10/10. **Kind:** retained baseline acceptance gap, not a new regression.

`generate` validates individual scalar fields but does not check canonical-name uniqueness.

with the same `name: alpha`. Metadata correctly refuses that source, but ordinary generation
returns exit 0 and replaces the valid catalog with two `/li:alpha` rows pointing to different
folders. A subsequent `--check` returns exit 0 and the ordinary success message.

retained in `confirmed-findings.json`. The pinned base produces the same duplicate output:
**not a new P13 regression**, but a retained gap against the current dispatch's explicit
"ambiguous inventory ... before JSON/write" requirement. Valid-output compatibility passes.

**Fix:** reject duplicate/case-equivalent skill names before opening output, retaining the
stdlib-only path and valid bytes/messages. Test valid-catalog preservation and refusal to
certify an already-generated ambiguous inventory.

**Evidence:** `confirm-valid-generation`, `confirm-duplicate-skill-json-control`,
`confirm-ambiguous-generation`, `confirm-ambiguous-check`, `confirm-baseline-call.json`,
