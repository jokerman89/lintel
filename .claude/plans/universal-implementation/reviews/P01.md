### P01-R1 - P2: ADR creation sweeps unrelated staged work into its commit

**Location:** `bin\li-adr-new:99-105`, especially line 104.
**Affected leaf:** A04.2; R01/R11 preservation. **Confidence:** high (reproduced).

`git add "$FILE"` does not restrict the following plain `git commit` to that file.
In a fixture with an unrelated tracked `operator.txt`, stage one version, then leave
another version unstaged and invoke `li-adr-new "Owned decision"`. The helper exits 0,
but the new ADR commit contains both the ADR and `operator.txt`; the previous staged
diff is consumed. The unstaged file bytes survive, so this is not a claim that the
working file was deleted or overwritten. It is an unauthorized inclusion of unrelated
user work and loss of its prior staging state.

Observed committed paths:

```text
.claude/decisions/0001-owned-decision.md
operator.txt
```

The commit block predates this patch, but the argument fix makes it reachable through
the documented invocation. This is directly coupled to the expressly required ADR
ownership/preservation boundary, not a request to repair an unrelated workflow.
The new ADR tests (`tests\unit\universal-trusted-tools.py:486-522`) exercise only a clean
index and therefore miss it.

**Required repair:** commit only the generated ADR while retaining unrelated index and
worktree state, or refuse the unsafe operation explicitly before mutation. Add a fixture
with both staged and unstaged unrelated changes and assert the exact committed paths,
unchanged unrelated index contents and unchanged worktree bytes. Do not use a reset or
stash/pop recovery that can clobber the operator's work.

### P01-R2 - P2: malformed performance values are silently truncated into valid metadata

**Location:** `hooks\shared\tq-perf-regression-warn\run.sh:61-76`.
**Affected leaves:** A25.2, A25.3 (approved metadata correction).
**Confidence:** high (reproduced).

The new `awk` matcher accepts a matching prefix rather than the complete field value.
For `p95_ms: 120oops` and `p95_ms: 120 999`, the hook exits 0, emits `p95 budget 120ms`,
and produces no error. `120.5` is likewise silently reduced to `120`: whether fractional
values are supported or rejected, changing the value is not faithful extraction.
This contradicts `hooks\shared\tq-perf-regression-warn\HOOK.md:19` and the package report's
claim that malformed present metadata is reported with exit 1. The new malformed-value
test at `tests\unit\universal-trusted-tools.py:336-347` checks only `invalid`, which has
no valid prefix.

**Required repair:** validate the complete present scalar before emitting it, with
explicitly supported whitespace/comment syntax. Reject invalid trailing content with
the documented non-blocking error; preserve valid values exactly. Cover numeric-prefix
garbage and journey-field suffixes as well as the existing wholly nonnumeric fixture.

### P01-R3 - P2: metadata lookup treats a literal filename as a regular expression

**Location:** `hooks\shared\tq-perf-regression-warn\run.sh:54-56`, called at lines 75-76.
**Affected leaves:** A25.2, A25.3 (approved metadata correction).
**Confidence:** high (reproduced).

With policy `custom/*` and an actual `custom/[id].txt` budget record containing
`journey: checkout` and `p95_ms: 120`, the hook exits 0 but omits both present values.
`grep "$1" -- "$file_edited" ...` interprets `[id]` as a character class, finds no match,
and the new absence-success branch turns the failed lookup into "optional metadata
absent". The earlier applicability lookup uses `grep -F`, so the two steps disagree
about the same path. Other regex characters can select the wrong record.

This is a retained defect in the rewritten, explicitly approved extraction boundary;
it is not a demand to implement the separate, broader host-event/path-normalization
work. The simple `custom/change.txt` fixtures at
`tests\unit\universal-trusted-tools.py:323-334` do not discriminate literal matching.

**Required repair:** use literal path matching consistently when locating metadata.
Add bracketed/metacharacter filename and nonmatching decoy-record cases; absence must
mean the record/field is actually absent, not that a regex reinterpreted its filename.
