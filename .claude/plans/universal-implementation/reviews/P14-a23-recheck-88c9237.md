### Q1 (P3): cross-test module execution to obtain the P09 signal

`setUpClass` runs the entire `tests/integration/domain-result-handoff.py` module through
`runpy.run_path` with a swapped `sys.argv` (`universal-a23.py:273-281`). It does this to
reuse its four-line `CHECK_CODE` and to put the installed bundle's `lib` on `sys.path`.

Running that module has side effects:
- it parses arguments;
- it creates `p09-fixture/<uuid>`;
- it leaves the `sys.path` entry in place for the rest of the process.

Any change to that unrelated test's module-level code can then break A23 in ways that
are hard to diagnose. The release asked for reuse, so this is deliberate, but the coupling
is broader than the one constant needed.

**Recommendation:** when next touched, read the signal as data, or insert the bundle `lib`
path explicitly, and keep the actual P09 check execution.

### Q2 (P3): one report sentence over-generalises the 7-file inventory

`reports/P14.md:2401` says "Every actual caller inventory contains 7 files including its
profile-history record". The 7-file observation is test_04b's `repo-policy-caller`, which is
the recorded case `actual-selected-source-caller-history`. Other caller inventories are much
larger; the installed `caller` includes its whole `.github/lintel` bundle. The evidence
itself is correct. Suggested wording: "the recorded source-policy caller inventory contains
7 files" in each run.
