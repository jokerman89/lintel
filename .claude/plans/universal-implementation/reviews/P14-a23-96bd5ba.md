## Findings

### F1 (P2): a PowerShell selector the unit never uses turns the Windows CI entry red

`LocalRun.check_environment` raises on Windows unless `LINTEL_POWERSHELL` names
`pwsh.exe` (`tests/integration/universal-a23.py:98-100`). The check runs before any import
or installation, and the `.sh` forwards the variable only when the caller sets it
(`universal-a23.sh:36`).

Nothing the unit exercises reads that variable or starts PowerShell:
- Installation uses `li-lifecycle.py` and the adapter.
- The only product reader of `LINTEL_POWERSHELL` is `install/install.sh:19-29`, which the
  unit never calls. A `git grep` of `bin/`, `lib/` and the reused
  `tests/integration/domain-result-handoff.py` finds no other PowerShell use.
- The existing tests that do use PowerShell treat the selector as optional
  (`tests/integration/universal-lifecycle.py:1119-1120`, `:1128`).

The repository's CI runs `bash tests/runner/run-all.sh --require-all` on `windows-latest`
without that variable (`.github/workflows/ci.yml:21`, `:25`, `:55`). The runner invokes
each entry with no arguments and no extra environment (`tests/runner/run-all.sh:90`). So
the committed test fails the Windows job, and any ordinary local `run-all.sh`, with a
traceback. My selector probe reproduced this: exit 1.

The report treats this as a "CI environment requirement" for the coordinator
(`reports/P14.md:2217-2218`, `:2236`). But the requirement is self-imposed and removable
inside P14's scope.

**Recommendation:** drop the Windows-only requirement, or validate the selector only when
it is present. Keep refusing every other ambient `LINTEL_*` selector. No CI change or
permission is needed.

### F2 (P2): preservation inventories silently skip files beyond `MAX_PATH`

`LocalRun.tree` lists files with `root.rglob("*")` and `path.is_file()`
(`tests/integration/universal-a23.py:199-203`). On Windows without long-path support
(this host has `LongPathsEnabled=0`), `is_file()` returns False for a path over
`MAX_PATH` instead of raising. The file is dropped from both the before and after maps, so
the equality check passes without observing it.

- **Observed:** in my runner-form root the caller history record
  `repo-policy-caller\.claude\runtime\lintel-home\sessions\profiles\<64>\history\1-<64>.json`
  is 269 characters. The probe shows the ordinary inventory sees 6 of that caller's 7
  files, and the native walk sees all 7.
- **Affected check:** test_04b's "caller unchanged" assertion (`:375`, `:379`) therefore
  never examines the caller's profile history. The card requires that check ("caller
  pin/home ... remain unchanged").
- **Why the owner's runs missed it:** their 25-character explicit roots top out at 235
  characters. The default root sits under `TMPDIR`, which is 59 characters here and is
  comparable on a typical user profile.
- **Wider impact:** the same helper backs every caller, home and bundle comparison
  (`:272-276`, `:291-299`, `:344-360`, `:398-400`, `:410-416`, `:651-654`). A deeper
  `TMPDIR` or longer fixture names would drop more files, the caller pin included.

Hosted runner long-path support is unverified.

**Recommendation:** enumerate and read through the accepted same-location native spelling
(`lib/context_safety.py` `native_io_path`, as P07/P10 do). Otherwise, fail when a native
walk's file count differs from the observed inventory. Also add a path-budget assertion
for the default root.
