limit. Actual HTML outside code still exposes its literal opening attributes.

### Exact provider API and consumer boundaries

`classify_markdown(text: str) -> MarkdownBoundaries` accepts the complete, unchanged
supplied Unicode string and rejects invalid input types explicitly. It is standard-library
Python 3.9-compatible code with no file, subprocess, network, task ID, policy or normalization
operation. `original` retains the same string object; the results and nested collections
are immutable NamedTuples/tuples.

The module is the single declaration of the approved record fields:

| Record | Fields |
|---|---|
| Span | start, end |
| Container | id, parent_id, kind, marker, content_column |
| LineBoundary | start, end, next_start, body, content_start, residual_indent, container_ids, kind |
| Region | span, kind, tag |
| ListItemOccurrence | marker, content, line_index, container_ids, classification |
| MarkdownBoundaries | original, lines, containers, regions, list_items |

Spans are zero-based half-open **Unicode codepoint** positions in the original input,
not bytes or rendered/stripped text. CRLF occupies two positions; line end excludes
terminators and next-start includes them. Both may equal EOF. Container IDs are local
to a classification. `content_column` is the visual column immediately after that
opening marker's syntactic padding, measured with four-column tab stops. The original
content span retains residual whitespace, including a tab supplying residual columns.
Regions are deterministically ordered and can overlap.

The helper consumes compound quote/list prefixes before block classification and records
actual structural marker occurrences, not continuation text or checkbox-shaped examples.
First-line item `classification` is prose, quoted, literal or unknown. Prose describes the
start context; it does not declare every later region safe to reinterpret. Full original
source and explicit region facts must accompany a later selected-leaf/checkbox/excerpt
consumer. No task semantics or clearance follows from this provider alone.

Unlike the old internal class, explicit spans now cover same-line PRE/CODE/SCRIPT/STYLE
bodies, comments, declarations/opaque HTML and unknown/incomplete constructs. Inline,
fenced and indented code and quote contexts remain explicit. Unterminated/ambiguous
material remains significant rather than being silently erased. Recognized opening
HTML tags remain distinct from their raw bodies.

Navigation consumes the provider's original-coordinate facts, not a second block parser.
Its permitted opening-tag attribute view preserves script `src` and quoted-delimiter
`href` references, including inside opaque HTML blocks, without interpreting raw-body
Markdown-shaped strings as links. Destination/reference/title parsing and source/target
privacy policy stay in the generator. The only changed old unit expectation is the
declared line-kind name (`indented_code` rather than the old internal `code`) and field
name (`residual_indent`); no prior behavioral assertion was removed.

### Shared-boundary implementation

`MarkdownSource` measures container-relative columns before classifying prose, blank,
code and raw continuation lines. Quote and ordered/unordered list prefixes are consumed
with a common container stack, including nested/compound containers and partial tab columns.
Fences and indented code use the same residual body; genuine paragraph continuation remains
prose. A length-preserving internal projection masks prefixes/code for parsing without
editing the supplied source or losing destination offsets.

Every recorded span is a zero-based, half-open Python Unicode-codepoint range into the
original supplied text. CRLF occupies two original positions; line end excludes its
terminator and next-start includes it. At EOF, line end and next-start equal input length.
Reference completion validates the consumed destination, optional title and allowed trailing
whitespace against that logical boundary. It never appends a physical newline or accepts
arbitrary trailing text to make a definition pass.

The same classification supplies limits for both reference passes and inline parsing,
and supplies the code/prefix mask used by the unchanged structured HTML reader. Literal
script opening attributes remain collected; raw bodies, pre/code and comments remain
excluded by their existing HTML/inline handling. No HTML or script executes. Public
source-only destination rewrites preserve the original container prefix, title and EOF.

The internal line model is not a published task-normalization API. In a coordinator-requested
read-only feasibility probe, a compound list fence classified as code, but same-line raw
pre/comment checkbox text remained in the projection until navigation's later exclusion
stage; opaque context IDs and `content_start` also do not prove actual list-marker ownership.
These limits were reported explicitly. No extraction to a shared module or P05 source edit
occurred, and no policy/review normalization claim follows from this navigation model.

### Root repair and invariants

HTML tag/attribute interpretation now uses Python's standard-library `HTMLParser`, retaining
source spans with a quote-aware attribute lexer. Opening `href`/`src` values, including
script resources, remain visible even when preceding quoted values contain `>`. Comments
and raw script/style bodies are not treated as navigation. Pre/code examples stay excluded;
no HTML, JavaScript or CSS is executed. First-attribute semantics, character references,
quoted/unquoted values and multiline tags retain the actual source destination span.

Markdown uses a lexical scanner with explicit code, label, destination and title states,
balanced delimiters, and two-pass forward-reference resolution. Escaped opening syntax
remains plain text; ASCII punctuation escapes are decoded before the existing path-safety
checks. Wrapped and nested labels no longer depend on a single-line regex. Used references
resolve to their first definition; unused or shadowed definitions do not select resources.
The earlier exclusion fixture now explicitly uses its intended reference rather than
asserting that an unused definition must be bundled.

One decoding convention serves ordinary, angle-delimited and escaped destinations.
The parser returns source spans rather than rewriting whole tags or examples. Code fences
in lists/quotes, inline/indented code, comments and template examples remain excluded.
A backtick cannot consume unrelated paragraphs. Script-body backticks do not create
Markdown fences. Literal dollar characters are no longer mistaken for unspecified templates.
Absolute/Windows/escaping paths are still rejected after grammar decoding.

The existing bounded public-document traversal, source-only labels, no-private-read rule,
managed ownership and missing-target refusal remain. Text assets, including scripts and
HTML, still normalize to LF; binary bytes remain untouched. This is not a blanket promise
of a full Markdown renderer or dynamic dependency analysis, and no valid reported navigation
was reclassified as unsupported to hide a failure.
