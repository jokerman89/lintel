## Q1 bounded-matcher quality repair

Read the full `reviews\P03-recheck.md` at
`98515a1c4db4796d03005529d61f021bcc2d0df1`, including its comparison-count evidence
and exact CLI replay. That report records specification PASS, F1-F4 closed, and full
quality FAIL with **one new P2, Q1**, at `context_safety.py:176-180` in `133eebe`.
No other new product quality finding was reported.

Before this repair, new tests reproduced all three relevant failure mechanisms:
the actual CLI exceeded five seconds for twelve adjacent `**/` segments on a twenty-directory,
one-byte fixture; consecutive and separated globstars exceeded deterministic comparison
bounds; and long path/rule sequences exhausted Python recursion. Persisting the repeated
pattern in the cooling file caused the same excessive work during literal selection.
The original candidate/file/byte limits did not constrain that matching work.

Commit `500adb3` changes only the matcher and its existing tests:

- Adjacent `**` segments collapse to one equivalent rule for matching. Original selector
  strings and persisted cooling records remain unchanged and visible.
- Iterative rolling rows replace recursive backtracking. Each path/rule state is evaluated
  once; the state bound is `(path parts + 1) * (normalized rules + 1)`. DP storage holds
  two rows, each proportional to the normalized rule count. Separated globstars use the
  same bounded algorithm; normalization alone is not the fix.
- The segment comparison function, including its actual-filesystem case-alias probe, is
  unchanged. Whole-path matching, literal metacharacters and F4's prefix-file guard remain.
- No new pattern cutoff, recursive-glob ban or success-shaped error fallback was added.
  A valid no-match remains unmatched/exit 1; actual matching errors remain explicit exit 2.

| New regression | Measured behavior |
|---|---|
| `test_globstar_comparisons_are_bounded_by_distinct_states` | On a 21-part path, twelve adjacent globstars allow at most 21 segment comparisons; twelve separated globstars allow at most 273. Both match and no-match cases are checked. |
| `test_separated_globstar_states_are_compared_at_most_once` | Unique path/rule spellings let the test reject any repeated segment-comparison state, not just slow elapsed time. |
| `test_globstar_long_paths_and_rules_do_not_use_python_recursion` | 1500-component synthetic path/rule inputs retain true/false results without recursion. These are matcher-string tests, not a claim about OS path-length support. |

## Mechanisms and retained value

`bin\_context.sh` remains the checkpoint owner: canonical target identity, repository-key
filenames, branch selection, v5 paths, exact-owner legacy discovery, list/latest and
explicit historical reads are retained. The shared Python reader adds bounded manifests
and future exclusions rather than introducing another checkpoint store. Empty reservations
are not discoverable; same-second saves cannot clobber an earlier save. Plain directories
and unborn branches have exercised checkpoint paths. Detached `HEAD` history is explicitly
preserved and now covered rather than inferred from the ordinary branch cases.

The normalized-path/reparse checks follow the existing `bin\li-copilot.py` safety contract
and are shared by P03's selector/snapshot code. The existing generator was not refactored
outside ownership. Selection accepts literal argument values or quoted globs, preserves
spaces/metacharacters as data, shows exact sources/digests/sizes, and surfaces missing,
excluded and bounded-out candidates. Actual Markdown and YAML ADR metadata are recognized;
unknown metadata remains visible rather than implying there are no constraints.
The Q1 repair now bounds globstar state evaluation for both source selection and the
persisted cooling consumer without changing those selection or identity contracts.

File snapshots are separate from Markdown continuity notes. A snapshot contains verified
pre-images and an explicit owner. A once-bound operation-result receipt must cover exactly
the owned paths before changed bytes can be restored. All paths/blobs/current states are
preflighted; later user edits conflict. The version-2 restore journal persists intent before
each mutation and verified completion afterward, retaining per-file filesystem observations.
Completed permissions cannot be reacquired through the original operation receipt.
An ambiguous transition may recognize a verified original without writing it; changed
states are refused. Aggregate-only version-1 recovery journals are preserved but cannot
establish safe automatic resume; snapshot/result formats stay unchanged.
Per-file atomic replacement and this journal avoid broad checkout, root deletion or recursive
tree replacement. Retention protects the union of newest five and recent thirty-day copies,
plus active/unsupported-journal recovery. Pruning requires exact eligible IDs and refuses unexpected content.

The roles retain their methods: deterministic good/bad reproduction, bisection, root-cause
verification, behavior-preserving refactoring, migration pre/post checks and reversible
plans. Trials are attributable and isolated; bisect exits on success/error. A partial
migration is not automatically undone unless the exact approved/rehearsed state and
authorization match and there are no external side effects.

URL policy distinguishes exact hosts from explicit wildcard subdomains. A checked,
transport-independent redirect loop validates before every next request, retains provenance
and rejects loops, HTTPS downgrade, malformed authorities, unauthorized hosts and oversized
responses. External content remains data, not instructions.

Budget/perf/cool entry points remain useful without invented control: capacity and usage
stay unknown when unavailable, byte estimates are labeled, perf preferences are advice only,
and cooling writes a root-bound exclusion file actually consumed by future selections.
Cooling removes zero active-context tokens and zero source-file/disk bytes.

## Explicit limitations and safety

- Independent specification recheck passed at `133eebe`; full quality rejected Q1.
  This candidate awaits the independent Q1 quality recheck and affected preservation
  confirmation. No self-approved completion, human review bypass, shared task-state write
  or integration was performed.
- Snapshots support regular owned files and recorded modes, not arbitrary filesystem
  metadata, services, live database/API rollback or credentials. Recovery requires an
  isolated/quiescent target; this is not a portable cross-process compare-and-swap guarantee.
  Snapshot activation and each replacement are atomic, not the entire multi-file restore.
- Ordinary interruption resumes through the journal. Process kill/machine loss may leave
  an operation lock; verify no active owner before explicit exact-lock recovery. Bisect
  traps cannot execute after a hard kill; its preserved trial requires inspection/reset.
- Recovery observations use file identity, size, mode and modification/change timestamps
  plus content digests; they are not a tamper-proof audit against an actor who can rewrite
  the snapshot/journal or forge filesystem metadata. This limitation does not excuse
  sequential user edits: the exact F1 sequence is now refused between separate invocations.
- Case aliases were tested on the native Windows filesystem. The distinct-case directory
  response is injected in a focused test, not an asserted live POSIX/Windows case-sensitive
  volume run. Matching now consults the filesystem instead of assuming its behavior from the OS.
- Q1 establishes polynomial path/rule state evaluation with bounded DP rows, not constant
  runtime for arbitrarily long inputs, a new wall-clock budget, or a timing guarantee on
  other filesystems. Existing traversal/file/byte limits remain separate controls.
- Old unmanifested `cp -r` backups are preserved but refused for automatic restore/prune.
  Owned legacy Markdown checkpoints retain automatic discovery; unattributed history
  remains available through an explicitly selected shared path. Old `context-ignore.md`
  notes remain readable but require explicit migration into consumed JSON exclusions.
- Python 3.10+ and Git are required by the checkpoint bridge. Missing tools fail explicitly.
  Other OS/client/model surfaces, live capacity changes, actual billing, live HTTP transport,
  current enterprise policies, full installer mutation and hard-crash durability were not
  verified by these fixtures.
- No dangerous recipe was run against this worktree or a personal/private tree. Mutation,
  symlink/junction, pruning, bisect/refactor/migration cases used disposable synthetic data.
  No remote Git/GitHub, credentials, push/PR, production, private sync or hook activation
  occurred. The memory compatibility test invoked an existing warn-hook directly only
  inside its synthetic fixture; nothing was registered or activated.
