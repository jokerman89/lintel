## Mechanisms and retained value

`bin\_context.sh` remains the checkpoint owner: canonical target identity, repository-key
filenames, branch selection, v5 paths, exact-owner legacy discovery, list/latest and
explicit historical reads are retained. The shared Python reader adds bounded manifests
and future exclusions rather than introducing another checkpoint store. Empty reservations
are not discoverable; same-second saves cannot clobber an earlier save. Plain directories
and unborn branches now also have exercised checkpoint paths.

The normalized-path/reparse checks follow the existing `bin\li-copilot.py` safety contract
and are shared by P03's selector/snapshot code. The existing generator was not refactored
outside ownership. Selection accepts literal argument values or quoted globs, preserves
spaces/metacharacters as data, shows exact sources/digests/sizes, and surfaces missing,
excluded and bounded-out candidates. Actual Markdown and YAML ADR metadata are recognized;
unknown metadata remains visible rather than implying there are no constraints.

File snapshots are separate from Markdown continuity notes. A snapshot contains verified
pre-images and an explicit owner. A once-bound operation-result receipt must cover exactly
the owned paths before changed bytes can be restored. All paths/blobs/current states are
preflighted; later user edits conflict. Per-file atomic replacement and a persistent restore
journal support interruption/resume without a broad checkout, root deletion or recursive
tree replacement. Retention protects the union of newest five and recent thirty-day copies,
plus active recovery. Pruning requires exact eligible IDs and refuses unexpected content.

The roles retain their methods: deterministic good/bad reproduction, bisection, root-cause
verification, behavior-preserving refactoring, migration pre/post checks and reversible
plans. Trials are attributable and isolated; bisect exits on success/error. A partial
migration is not automatically undone unless the exact approved/rehearsed state and
authorization match and there are no external side effects.

URL policy distinguishes exact hosts from explicit wildcard subdomains. A checked,
transport-independent redirect loop validates before every next request, retains provenance
and rejects loops, HTTPS downgrade, malformed authorities, unauthorized hosts and oversized
responses. External content remains data, not instructions.

Budget/perf/cool entry points remain useful without invented control: capacity and usage
stay unknown when unavailable, byte estimates are labeled, perf preferences are advice only,
and cooling writes a root-bound exclusion file actually consumed by future selections.
Cooling removes zero active-context tokens and zero source-file/disk bytes.

## Explicit limitations and safety

- Independent package spec/quality review has not run. No self-approved completion,
  human review bypass, shared task-state write or integration was performed.
- Snapshots support regular owned files and recorded modes, not arbitrary filesystem
  metadata, services, live database/API rollback or credentials. Recovery requires an
  isolated/quiescent target; this is not a portable cross-process compare-and-swap guarantee.
  Snapshot activation and each replacement are atomic, not the entire multi-file restore.
- Ordinary interruption resumes through the journal. Process kill/machine loss may leave
  an operation lock; verify no active owner before explicit exact-lock recovery. Bisect
  traps cannot execute after a hard kill; its preserved trial requires inspection/reset.
- Old unmanifested `cp -r` backups are preserved but refused for automatic restore/prune.
  Owned legacy Markdown checkpoints retain automatic discovery; unattributed history
  remains available through an explicitly selected shared path. Old `context-ignore.md`
  notes remain readable but require explicit migration into consumed JSON exclusions.
- Python 3.10+ and Git are required by the checkpoint bridge. Missing tools fail explicitly.
  Other OS/client/model surfaces, live capacity changes, actual billing, live HTTP transport,
  current enterprise policies, full installer mutation and hard-crash durability were not
  verified by these fixtures.
- No dangerous recipe was run against this worktree or a personal/private tree. Mutation,
  symlink/junction, pruning, bisect/refactor/migration cases used disposable synthetic data.
  No remote Git/GitHub, credentials, push/PR, production, private sync or hook activation
  occurred. The memory compatibility test invoked an existing warn-hook directly only
  inside its synthetic fixture; nothing was registered or activated.
