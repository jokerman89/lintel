## Final public API

Import `review_contract` from the **trusted installed source** `lib`, never target
code. It uses the sibling `review-schema.json` and `markdown_source.py`.
`ContractError` is the validation
failure type. `Json` below is `dict[str, Any]`; `Optional`/`Union` are Python 3.9
compatible. The source is authoritative for annotations.

```python
load_json(text: str) -> Json
validate_control(control: Mapping[str, Any]) -> Json
evaluate_controls(controls: Sequence[Mapping[str, Any]], *,
                  required_policy: Mapping[str, Any]) -> Json
snapshot(repo: Path, *, base: str, selection: Sequence[str],
         record_path: Optional[str] = None) -> Json
bind_work(repo: Path, *, work_map: Optional[str], package_id: str,
          leaf_ids: Sequence[str],
          acceptance_paths: Sequence[Union[str, Json]]) -> Json
validate_review(record: Mapping[str, Any]) -> Json
validate_decision(record: Mapping[str, Any], *, history: bool = False) -> Json
select_latest(records: Sequence[Union[Mapping[str, Any], ContractError]], *, skill: str,
              work_map: Optional[str], package_id: str) -> Optional[Json]
verify_review(repo: Path, record: Mapping[str, Any], *, expected: Json,
              corroboration: Optional[Json] = None) -> Json
```

Supporting public operations: `canonical_json(value)`, `content_digest(value)`,
`validate_shape(value, definition)`, `resolve_commit(repo, value)`,
`evidence_manifest(repo, controls)`, `validate_context(context)`,
`verify_context(repo, context)` and `verify_qa(repo, qa, *, expected)`.
Validation/control evaluation is pure; snapshot/work/evidence/verification functions
read Git/filesystem data and do not dispatch, execute artifact content or write logs.
`CONTRACT_VERSION = 2` identifies only bound review/context/QA. Standalone control
outcomes, inspection envelopes, profile references and corroboration keep their
existing versions.

The snapshot `head` is retained as provenance; its global value alone is not the
result digest. Per-selected-path HEAD/base/index/working states still bind. This
permits unrelated commits, not changed selected content. Acceptance may bind whole
files or explicit unique start/end-line excerpts. In mapped tasks only, recognized
selected-leaf checkbox progress is normalized; task text/IDs and raw product
snapshots remain unchanged. Use `bind_work`, not a consumer's raw file hash, to
derive this identity. Older contexts bound to already-checked raw task bytes may
need fresh preparation. Source task parsing/membership remains the work-map/Swarm
owner's responsibility; coverage must match the original authority.
All old byte-only mapped-excerpt bindings require fresh preparation and independent
review under the documented Q01 preimage, even when their visible text is unchanged.
No public field, CLI argument, API signature or durable schema version is added.

`select_latest` validates mappings before filtering. Decoder `ContractError`
candidates retain their original append position. It raises when the latest
applicable candidate remains invalid, rather than permanently poisoning the log
when a newer valid applicable review follows. Native audit envelopes support
explicit `review-v1`/`review-v2` formats. V1 is interpreted for history/order, never
auto-promoted to current clearance. Raw `--json` remains available.

### Immutable QA inventory and v2 migration

The unchanged `prepare --repo --request` command requires `qa_requirements` and
emits context v2. Each entry has exactly `id`, `kind`, `requirement`,
`applicability` and `policy`, using shared definitions. IDs are unique; mandatory QA
IDs must be in `required_controls`, advisory QA IDs must not be. The review must
carry matching QA controls. Mandatory review-only controls outside this inventory
are generic `check` criteria; bound typed validations cannot disappear from QA.

QA observations carry the exact inventory/immutable fields; only result data may
change. Missing IDs, tests-to-check conversions, mandatory-to-advisory labels, new
N/A scope and changed policy reject in both producer and consumer. A docs-only
context can declare document/check validation plus grounded tests N/A or genuinely
no test obligation. This neither invents universal tests nor derives requirements
from names/results.

The executable-check example in `skills/review/references/evidence.md` declares
`required_controls: ["spec","quality","tests"]` and a mandatory applicable `tests`
entry with its accepted policy. Context, review and QA are v2; corroboration remains
v1 and binds the complete new review digest. Reprepare and independently review;
do not change old version numbers, add guessed obligations to old evidence or
rewrite history. New bound v2 decisions may supersede old entries; later bad
candidates still revoke. CLI flags and `verify_qa(repo, qa, *, expected)` are unchanged.

`required_policy` has five required keys: `required` (boolean), `status`
(`loaded|not_required|unverified|error`), `source` (string/null), `version`
(string/null), `applicability` (`applicable|not_applicable|unknown`). `reason` is
optional nonblank text. Empty/null source/version can express unresolved input but
cannot clear a required policy. No copied fallback can turn `PROFILE_REQUIRED` or
`PROFILE_DRIFT` into loaded.

The optional supplied profile reference is exactly:
`{schema_version:1, context_id, generation, digest:"sha256:...", name, version}`.
Call P07's actual `verify_profile_reference` before consuming it. P05 compares the
entire expected reference and binds the local required-policy declaration; it does
not discover private profile homes or authenticate a previously copied reference.
