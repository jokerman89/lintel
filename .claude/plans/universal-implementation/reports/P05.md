## Outcome

explicit Git/worktree identity, review writing/reading, read-only QA and SHIP.
Mandatory applicable failure/error/unverified outcomes block independently of
advisory scores. Empty/unbound commits, malformed/duplicate JSON, unknown status
strings, stale content and uncorroborated independence cannot clear the gate.

result explicitly has `release_clearance: false`. Strict SHIP requires mapped
authority and full evidence. A review digest binds content, not authenticated identity.

## Final public API

Import `review_contract` from the **trusted installed source** `lib`, never target
code. It uses the sibling `review-schema.json`. `ContractError` is the validation
failure type. `Json` below is `dict[str, Any]`; `Optional`/`Union` are Python 3.9
compatible. The source is authoritative for annotations.

```python
load_json(text: str) -> Json
validate_control(control: Mapping[str, Any]) -> Json
evaluate_controls(controls: Sequence[Mapping[str, Any]], *,
                  required_policy: Mapping[str, Any]) -> Json
snapshot(repo: Path, *, base: str, selection: Sequence[str],
         record_path: Optional[str] = None) -> Json
bind_work(repo: Path, *, work_map: Optional[str], package_id: str,
          leaf_ids: Sequence[str],
          acceptance_paths: Sequence[Union[str, Json]]) -> Json
validate_review(record: Mapping[str, Any]) -> Json
select_latest(records: Sequence[Mapping[str, Any]], *, skill: str,
              work_map: Optional[str], package_id: str) -> Optional[Json]
verify_review(repo: Path, record: Mapping[str, Any], *, expected: Json,
              corroboration: Optional[Json] = None) -> Json
```

Supporting public operations: `canonical_json(value)`, `content_digest(value)`,
`validate_shape(value, definition)`, `resolve_commit(repo, value)`,
`evidence_manifest(repo, controls)`, `validate_context(context)`,
`verify_context(repo, context)` and `verify_qa(repo, qa, *, expected)`.
Validation/control evaluation is pure; snapshot/work/evidence/verification functions
read Git/filesystem data and do not dispatch, execute artifact content or write logs.

The snapshot `head` is retained as provenance; its global value alone is not the
result digest. Per-selected-path HEAD/base/index/working states still bind. This
permits unrelated commits, not changed selected content. Acceptance may bind whole
files or explicit unique start/end-line excerpts; source task parsing/membership
remains the work-map/Swarm owner's responsibility. All selected leaf coverage must
be checked against the original authority.

`required_policy` has five required keys: `required` (boolean), `status`
(`loaded|not_required|unverified|error`), `source` (string/null), `version`
(string/null), `applicability` (`applicable|not_applicable|unknown`). `reason` is
optional nonblank text. Empty/null source/version can express unresolved input but
cannot clear a required policy. No copied fallback can turn `PROFILE_REQUIRED` or
`PROFILE_DRIFT` into loaded.

The optional supplied profile reference is exactly:
`{schema_version:1, context_id, generation, digest:"sha256:...", name, version}`.
Call P07's actual `verify_profile_reference` before consuming it. P05 compares the
entire expected reference and binds the local required-policy declaration; it does
not discover private profile homes or authenticate a previously copied reference.

See the executable recipes and data examples in
[`skills/review/references/evidence.md`](../../../../skills/review/references/evidence.md).

| Operation | Exact public command shape |
|---|---|

| Unmapped inspection | `... inspect --repo <target> --snapshot <snapshot.json> --input <controls-and-policy.json>` |

| Audit persistence | `bash <source>/bin/li-review-log --file <review.json>` |
| Latest applicable clearance | `bash <source>/bin/li-review-read --skill <gate> --expected <context.json> --corroboration <receipt.json> --gate-json` |
| Standalone lane verification | `... verify --repo <target> --record <review.json> --expected <context.json> --corroboration <receipt.json>`; not latest-log selection |
| Read-only QA evidence | `... qa --repo <target> --expected <context.json> --input <observed-test-controls.json>` |
| SHIP consumption | `... ship --repo <target> --skill <gate> --expected <context.json> --corroboration <receipt.json> --qa <qa.json>` |

Set `LINTEL_SOURCE_ROOT` and `LINTEL_REPO_ROOT` separately for shell adapters.
`--corroboration` is optional syntactically, but missing required independence blocks.
Host receipts are coordinator-provided observations; two names, a digest, a tool's
availability or a declared session binding cannot authenticate independence.

Shell `--json` is raw history only, not clearance. `--days N` adds an optional age
limit; it never establishes identity. Legacy writer calls need an actual commit and
an exact legacy status, but remain history-only. `--history` and explicitly selected
`GSTACK_HOME` imports preserve archived records without reissuing old decisions.
Unspecified personal legacy homes are no longer scanned automatically.
