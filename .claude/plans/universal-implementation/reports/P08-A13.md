## Implementation by leaf

### A13.1.a Common observation interface

- **Router** (`bin/_audit.sh`). One pure resolver behind `audit_dir`, `audit_file` and
  `audit_read_files`. Sourcing and resolving create no directories; `_audit_out_dir`
  stays and is side-effect free as well. `audit_log` keeps its signature, envelope,
  escaping, destinations and advisory exit 0, and creates its own directory just before
  writing. `audit_count` reads the first existing listed file and names a later existing
  file it did not read. With no log it prints nothing on stdout, writes `unobserved:`
  with the listed paths on stderr and returns 3. It reports records a since filter
  excludes for lack of `ts`, and its comment calls it an approximate counter.
  `audit_days_ago` fails visibly instead of silently widening the window.
- **Catalog** (`lib/event-catalog.json`, schema and catalog version 1). The envelope and
  vocabulary, 30 categories and 75 kinds with producers, `records_when`, fields,
  aliases and ordered class/check rules. The `_jobs_audit` wrapper, four dynamic
  entries (see deviation 2), the delegated `reviews` category and
  `non_recording_hooks` (`context-bloat-warn`). The Claude-home migration producer
  carries a note that P10 replaces it at fan-in. Integration reduces the counts from 30
  categories and 75 kinds to 24 and 69 as coordinator reconciliation 4 (authority
  `5c13c68c` alongside `84e63a4e`): accepted P09 removed the instruction-only producers
  of `da-decisions`, `dh-decisions`, `sc-decisions`, `ta-decisions`, `tq-decisions` and
  `full-engineering-pass`; this branch keeps them because its skills still contain
  those producers, and the final whole-P08 review assesses the reduction.
- **Reader** (`bin/li-events.py`, stdlib only, `sys.dont_write_bytecode`). `summary` and
  `records` over explicit files, with `--category`, `--kind` and `--since`. It emits
  `malformed_json`, `duplicate_key`, `missing_envelope`, `non_string_value`,
  `unknown_kind`, `undated` and `incomplete_tail` diagnostics and follows the contract's
  exit precedence (2 usage or unreadable catalog, 4 diagnostics, 3 unobserved, 0 valid).
  It writes nothing.
- **Consumers.** `hooks-status`, `audit`, `usage-log`, `maintenance` and `retro` read
  through the reader or `audit_read_files` and report absence as unobserved. They issue
  no dead, never-invoked or "nothing ran" verdict, and a block record is not presented
  as proof of host enforcement. `lib/scale-estimator.sh` reads granularity through
  `audit_read_files`. `hooks/shared/README.md` states what hooks record.
- **Mandatory writers** (`bin/_jobs.sh`). `job_create` writes `job.yaml` through a
  byte-verified staged file. `job_set_steps`, `job_update` and `job_archive` replace the
  record only when the rewrite succeeded and has the expected line count. A failed or
  short write returns non-zero with an explicit message and keeps the previous record.
  The `jobs.jsonl` line stays advisory. `job-begin` prints "Job started:" only after a
  written record. The `jobs` skill names the records the helpers actually write.
- **Ledger diagnoses.** `state_cycle_segment` reports an unknown `entry_format` as
  `state_diagnostic: unsupported entry format` with status `UNTRUSTED` and
  `cycle_complete: false`. Legacy blocks keep their status and gain
  `completeness: unknown (legacy entry)`. The footer labels INCOMPLETE and UNTRUSTED.
  The session digest renders its cycle line through `render_cycle_footer`, so no
  second ledger parser remains in the hook.

### A13.2 Lesson store and promotion

- **Grammar.** Headings are `## L-<digits> — <title>` (or ` - `) outside fenced code. A
  block ends before the next level-two heading outside a fence. Supersede markers may
  sit on any block line, behind `> ` and with trailing text. Unparseable and duplicate
  headings, missing supersede targets and dated legacy headings are reported on stderr.
- **Two implementations.** The awk program in `lib/memory.sh` serves surfacing, counts,
  the digest (`lessons_recent`), `lessons_index` and budget reads with unchanged stdout.
  `bin/li-lessons.py` provides `inspect`, `next-id` (highest existing plus one, never
  reused), `get --id`, `add`, `update` and `supersede`. Writes take the mkdir lock
  (`LINTEL_LESSONS_LOCK_SECONDS`, default 5, never broken) and replace the store only
  when it is unchanged. Both pass the shared oracle in `tests/fixtures/lessons/`.
- **Stores.** The project store is the `lintel_lessons_file` resolution. A second
  existing store is reported as ignored, and outside a repository the result is
  "no project lessons store (unobserved)". Without Python 3.9+, `lessons_helper` and the
  promotion wrapper refuse visibly while the awk reads keep working. The global scope
  refuses; `~/.lintel/lessons.jsonl` remains a read-only legacy view.
- **Skills.** `capture`, `learn`, `lessons`, `lessons-surface`, `sense`, `discover` and
  `skillify` allocate, retrieve by ID and count through the two entry points.
- **Promotion.** `bin/li-lessons-promote` is a thin wrapper around
  `li-lessons.py promote`. It parses arguments and `--help` before any source
  resolution and selects the lesson with `--id`. The destination comes only from
  `--lintel-dir` or `LINTEL_DIR`, and non-interactive use requires an explicit
  `--source-label`. The generalized file must have exactly one level-two heading, which
  is rewritten to the destination's next ID, and one provenance comment is appended.
  Duplicates stop with the existing ID. Default mode writes only the target and prints
  its diff. `--commit --expect-branch` checks its preconditions before any write,
  commits only the target, verifies the parent, path and refs, and uses exits 8-11 as
  the contract table defines. It never resets, switches, creates a branch or pushes.
- **Surfaces.** The scaffolding baseline, the `job-end` hook and `HOOK.md`,
  `docs/concepts/jobs-system.md`, `docs/concepts/memory-v2.md`, `CONTRIBUTING.md`,
  `docs/faq.md` and `docs/power-user.md` follow the grammar and the promotion rules.
  Job lesson candidates are only suggested for review, never appended. The digest shows
  the three active lessons with the highest IDs.

## Deviations from the contract

1. **Test edits after the RED run.** The RED run used an earlier text of the tests.
   Four changes followed:
   - the undated fixture line in `test_audit_count_reports_absence_and_undated_exclusions`
     uses `audit_log`'s compact separators, because `audit_count` greps the writer's
     real format;
   - a `product_stderr()` filter drops the MSYS line
     `bash.exe: warning: could not find /tmp, please create!` in two exact-stderr
     assertions, because this host emits it whenever its `/tmp` mount is stale;
   - the consumer-wording test exempts the phrase "not evidence that nothing ran",
     which the contract itself prescribes for the audit reader;
   - the catalog test treats a wrapper's forwarding `"$@"` call as non-literal, matched
     by the wrapper's dynamic entry.
2. **A fourth dynamic entry (accepted by the coordinator).** The contract lists three
   dynamic entries, but its coverage rule requires every non-literal kind to match one.
   `bin/li-review-log` calls `audit_log reviews "$skill"`, so the catalog adds a
   `bin/li-review-log` entry whose kind is the reviewed skill name, with `reviews`
   delegated to `li-review-read` and never classified.
3. **Lesson audit records.** `bin/li-lessons.py` writes
   `lesson_recorded|lesson_updated|lesson_superseded` through three literal
   `audit_log lessons <kind>` case arms in a bash subprocess. They are catalogued as
   literal producers (55 to 58 calls) instead of a fifth dynamic entry. Promotion
   records an advisory `lesson_recorded` with `scope=promotion` and
   `classification=promote` in the source repository's scope, never in the destination,
   which default mode must leave with only the target changed.
4. **Reader details the contract leaves open.** A record without `ts` is `undated`,
   not `missing_envelope`. Undated records are valid and counted without a `--since`
   filter and are excluded with an `undated` diagnostic under one. A `by_kind` row
   whose records classify differently has null `class` and `check` plus a
   `breakdown`. Delegated `reviews` rows have null class, check, fields and normalized
   values and `delegated: li-review-read`.
5. **Exit codes outside the contract table.** In promotion, the required refusal of a
   `--source` outside a Git work tree exits 3; a missing Python exits 2 with a visible
   refusal; a `--lintel-dir` that is not the top level of a Git work tree exits 4,
   because the target and the path-limited commit are anchored there; a malformed,
   absent or duplicated source ID exits 6. For lesson writes, which have no table: an
   absent target exits 1; a duplicated or already superseded target and the global
   scope exit 2; no resolvable project store or a location outside a repository exits
   3; a write or lock-directory failure exits 4; a held lock or a store changed during
   the write exits 9.
6. **"Short write" for rewrites.** The contract does not define it. `job.yaml`
   creation compares every byte; a rewrite must produce the expected number of lines
   (unchanged for `job_update`, one more for `job_archive`, prefix plus steps for
   `job_set_steps`). A structural check was rejected because it refused valid records
   without a `steps` block.
7. **Additional truthfulness corrections in owned files.** `code-unfreeze` also
   claimed that `/help` shows the freeze state; both freeze skills now name their exact
   audit keys; `maintenance` no longer claims to write `maintenance-runs.jsonl`; the
   limitations bullet in `docs/power-user.md` said the freeze was "enforced by the
   skills that check it".
8. **Citations and display.** The contract cites `docs/concepts/jobs-system.md:69`
   from an older tree; in the base the statement is at line 80, and that line was
   changed. The digest's cycle line drops its " — /li:resume to continue, or
   /li:status" suffix because the shared compact footer already carries the resume
   instruction.
