## Exact shared API

### Python producer and consumers

All functions below come from `lib/profile_context.py`; no caller should reparse
pack manifests or rebuild a fingerprint independently.

```python
config = ProfileConfig(
    source=approved_source,
    repo=temporary_repo,
    home=temporary_home,
    packs=temporary_home / "packs",
    pointer=temporary_home / "packs" / "active-pack",
    context_id="synthetic-work",
)
record = load_profile_context(config, create=True)
reference = profile_reference(record)
verified_record = verify_profile_reference(reference, config)
policy_load = required_policy(verified_record)
```

`ProfileConfig` normalizes paths itself. Additional fields are
`context_file: Path | None = None`, `explicit_pack: str = ""`, and
`expected_reference: dict | None = None`. The latter uses the same strict reference
schema and makes every `load_profile_context` call verify the expected generation,
even if `create=True` was supplied; it cannot recreate a lost resume pin.
Other public operations are `resolve_profile(config)`,
`validate_profile_reference(reference)`, `bootstrap_profile_context(config)` and
`rebind_profile_context(config, reason)`. Normal consumers verify before use;
`create=False` is the default for `load_profile_context` and missing resume state
is not silently recreated. `ProfileError.code` distinguishes required load,
baseline, drift, reference/context/input and compatibility failures.

The strict reference is exactly:

```json
{
  "schema_version": 1,
  "context_id": "synthetic-work",
  "generation": 1,
  "digest": "sha256:<64 lowercase hexadecimal characters>",
  "name": "synthetic-strict",
  "version": "1.2.3"
}
```

The record additionally holds source/target roots, selection mode/status, complete
ancestry and baseline identities, typed effective values, field provenance, input
hashes, compatibility decisions, rebind reason and previous reference.

P05 owns the canonical `required_policy` schema. The producer emits
`{required, status, source, version, applicability}`, a valid subset of that schema
(optional `reason` is omitted). Loaded required policy has nonblank source/version
and known applicability; neutral/optional is `not_required`/`not_applicable`, not
verified compliance. No competing control schema is defined here.

### Shell compatibility and new functions

Preserved: `get_active_pack_name`, `get_loaded_pack`, `validate_pack`,
`resolve_pack_field`, `pack_field_is_true`, `pack_is_extension`, `pack_namespace`,
`pack_workflow`, `clear_pack_cache`. Known internal directory/chain/field wrappers
also remain; `_pack_dir` retains native-to-MSYS spelling for existing shell callers.

Added: `pack_compatibility`, `resolve_pack_field_json`,
`profile_field_provenance`, `profile_context_json`, `profile_context_reference`,
`profile_required_policy`, `bind_profile_context <id>`,
`verify_profile_context [reference-file]`, `rebind_profile_context <reason>`.

Profile failures exit nonzero without success-shaped values. The deliberate
exception is `profile_required_policy`, which emits structured `status:error`
metadata **and still exits nonzero** for P05's consumer. Missing optional legacy
field reads remain empty; typed field reads distinguish absent status 1 from
explicit JSON null status 0. Raw cache parsing is no longer an API.

Successful direct shell verify/bind/rebind exports the exact JSON reference as
`LINTEL_PROFILE_REFERENCE`. Every subsequent accessor and inherited process uses
the shared validator to check its context, generation and digest. A resumed
invocation requirement is retained without repeating `LINTEL_PROFILE_PACK`.
A later rebind, missing pin or corrupted reference cannot neutralize subsequent
policy reads. Missing/invalid transported policy remains `required:true`,
`status:error`, `applicability:unknown` with a nonzero exit.

### Precedence, lifecycle and fingerprint

Repository `.claude/profile-requirements.json` is read before the possibly broken
pack. It contains exactly `schema_version: 1` and `required_pack`. Conflicting
explicit selection fails. Otherwise explicit `LINTEL_PROFILE_PACK` is required,
the legacy active pointer is optional, and no selection is neutral first use.
Named source precedence stays configured store -> target packs -> source bundle.

`lintel_copilot_env <target> [context-id]` preserves approved explicit source,
target/home/store configuration and binds/verifies before returning. Without a
supplied stable identity it atomically selects a repository work reference at
`.claude/runtime/profiles/selected.json` and exports its ID. This is not a fake host
session ID. One-shot direct reads remain usable but cannot claim a pinned handoff.

SHA-256 covers canonical profile data and raw-byte hashes for pointer, requirements,
manifest ancestry, neutral defaults and compatibility source. It includes source
identity, effective values and origins, not only names/versions/mtimes. A reference
also binds context and generation. Rebind requires a reason, validates first, keeps
`history/`, updates only a matching selected work reference and invalidates old
references. Different target/source roots are not silently transplanted as resume.
Rebind now uses the same repository-selection -> context lock order as bootstrap
and publishes both current and selected records inside that transaction. A stale
same-context selected reference can be recovered only if retained history
corroborates it; a different context's selection is preserved.

### Compatibility and migration

- `schema_version`: supported manifest syntax, independent of the product.
- `version`: the pack release.
- `requires_lintel_product`: actual source `.claude-plugin/plugin.json` version.
- `requires_capabilities`: resolver feature contracts from `lib/pack-schema.yaml`,
  not host permissions or observed operations.
- Exact `requires_lintel: ">=4.0.0"`: historical pack-v1 marker. Other historical
  ranges need explicit migration, never a guessed public-version comparison.

Ranges use full semver with `=`, `==`, `<`, `<=`, `>`, `>=` and conjunctions.
Unsupported syntax is explicit. Missing product metadata is allowed only when no
product constraint was requested; it is not verified product compatibility.
Legacy YAML cache files are not trusted as content-bound resume evidence and are
not deleted. Use a new verified context/replan rather than silently importing one.
