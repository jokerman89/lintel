## Implemented behavior

The existing generator now exposes a documented `--json` read/query mode, not a second
inventory or routing engine. It reads only bounded opening frontmatter for discovery,
uses the accepted P06 registry reader for surface aliases, and reuses the existing strict
`envelope_contract.load_text` data loader for YAML. All executable readers remain bound
to the invoked trusted helper. An explicit absolute `--source-root` changes data only;
target-provided Python decoys are not imported.

Queries/searches, exact names, families, kind/category/voice and surface filters are
literal data. They cannot trigger generation, regex/glob evaluation, shell execution,
activation, profile binding or target writes. A malformed requested-kind inventory cannot
be hidden by an unmatched query. Missing/empty/malformed data, ambiguous identities or
aliases, invalid filters and missing helpers/dependencies fail before JSON publication.
Valid zero matches remain distinguishable from invalid input.

Catalog/help/router now query this helper first. Help no longer independently globs and
parses the corpus or advertises fixed hook counts as live state. Router shortlists at most
three entries before reading only selected bodies, removes personal telemetry access and
the unsupported offline/speed claims, and names actual host operations or explicit
canonical/serial/manual fallbacks rather than fictional tool names.

The current inventory has **127 skills, 69 agent roles and 46 retained skill aliases**.
Stable kind/name identities, source-relative paths, full descriptions and alias migration
notes remain visible. All maturity values are explicitly unknown. A frontmatter `full`
hint does not promote `TEMPLATE ONLY` to a completed format, or prove host execution.
Synthetic future-looking fields are not treated as an accepted capability contract.

The three caller frontmatters are unchanged in their canonical LF text representation.
The generated catalog was **not edited or regenerated**. Ordinary generation and
`--check` retain their default behavior, messages, platform stdout line endings and exact
canonical rendered bytes. Generation additionally refuses empty/repeated required fields,
unterminated quotes, collection/block values and bounded-header errors before opening
