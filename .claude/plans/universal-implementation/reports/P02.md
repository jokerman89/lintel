## Migration and retained behavior

The existing per-tool configuration filenames are retained:
`<HOME>\.lintel-roles-remote.txt` and `<HOME>\.lintel-lessons-remote.txt`. Explicit
`setup <repo-url>` writes JSON with `schema_version: 1`, a boolean `enabled`, the
selected URL and canonical local cache directory. A legacy URL-only file never
authorizes transfer automatically; the operator must run setup again.

Setup verifies exactly one effective fetch URL and one effective push URL, including
Git URL rewrites. Rebinding updates the actual origin, clears a stale local push URL,
and enables only after verification. It disables the previous binding before changing
an existing origin. It never resets, commits or deletes the existing cache. Initial
clones are staged and checked for local conflicts before importing missing content.
Existing local files are not overwritten by setup.

`forget` atomically records a disabled binding. It does not delete local files,
history, staged changes or the Git origin. Repeated forget is safe; reactivation
requires explicit setup. Missing/malformed bindings and mismatched origins fail
before staging, copying lessons or starting a Git transfer.

Lessons use `<readable-name>--<sha256>.md` records. Identity comes from the source
repository's origin, or its canonical Git common directory when no origin exists.
Local paths and equivalent file URLs normalize together; other remote spellings
are not guessed to be aliases. Source-repository names and identities are never
written in plaintext to a second project registry. Legacy basename-only records
are retained byte-for-byte rather than ambiguously reassigned or deleted.

Both entrypoints retain setup/push/pull/status/forget/help, default and `--status`,
and help aliases. `--push` and `--pull` also work. Role Markdown, nested role files,
ignore rules and Git symlink representation are retained. Lesson paths still come
from `lib\paths.sh`, including the existing legacy fallback. Pull updates the
private cache, never the source repository's lessons file. Failed pushes retain
their local commit for retry; Git errors remain nonzero and visible.

## Findings, boundaries and handoff

RU-03 is a **P1** audit finding addressed by this implementation and its negative
tests. No independent P1/P2/P3 review verdict is claimed. The implementer did not
delegate a nested agent or approve its own changes.

All transfer fixtures use temporary local bare Git repositories, with file-only Git
protocols, isolated HOME/USERPROFILE/XDG paths, disabled system/global Git config
and synthetic identities configured in the individual fixture repositories.
There was no GitHub/network operation, credential use, real private synchronization,
push/PR/default-branch mutation or user-global change.

Remaining boundaries:

- Independent package spec and quality review is pending with MasterSession.
- Actual remote privacy, credentials, network transports, Linux/macOS execution,
  native Bash 3.2 and actual Python 3.9 execution are unverified here.
- A moved origin or moved remote-less Git directory creates a new identity; previous
  records stay intact. Cross-protocol URL aliases are deliberately not auto-merged.
- Rebinding to an unrelated nonempty vault requires explicit manual history
  reconciliation; push/pull refuse rather than force-pushing, resetting or merging it.
- This is not a lock against a separate process changing Git/configuration during an
  operation. Enabled/current binding is checked at the action boundary, including
  again immediately before push.
- No full repository suite, consumer installation, CI or generated-output
  regeneration was run in this isolated package. Those belong to integration.

No outside-card documentation edits are required to keep existing descriptions true.
The entrypoint help documents explicit re-setup, disabled forget and retained records;
an optional coordinator-owned migration note can reuse the migration section above.
