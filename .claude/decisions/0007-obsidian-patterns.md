# ADR-0007: Obsidian integration — four patterns, write-only, pack-gated

**Status:** Accepted (2026-06-12)
**Decided by:** operator (D4 gate — adopt the four verified patterns, pack-gated; the sink stays write-only)
**Implements:** .claude/engineering/design-archive/lintel-v5-claude-home-memory-obsidian-design.md (workstream C)

## Context

The capture vault sink (PR #62) made Lintel write session summaries into an Obsidian vault.
The operator wants Lintel to leverage a user's vault workflow and make Lintel-connected repos
visualizable — without building only for Obsidian. Research verified which patterns carry
weight in 2026 (Bases over Dataview; deliberate wikilinks over graph tuning; index notes as
the cheap read path; write-only validated — the MCP read path is where token pain lives) and
which are hype (canvas generation, vault-as-memory claims, plugin sprawl).

## Decision

Ship exactly four patterns (D4):

1. **Locked flat frontmatter schema** on session notes — `created`, `type: session`, `repo`,
   `branch`, `outcome` (controlled vocabulary: shipped | in-progress | blocked | exploration),
   `tags`, `session`. The schema is the interface; everything else builds on it.
2. **`sessions.base`** (Bases core plugin) installed by the new `bin/li-vault-init` —
   dashboard + "Open threads" view. No Dataview dependency.
3. **Wikilinks**: every note links the repo hub (`<sink>/<repo>.md`, created if missing) and
   its predecessor session. Backlinks give per-repo history; the graph comes free.
4. **Agent-maintained `00-index.md`** regenerated by CAPTURE (newest 15, wikilinked).

Plus: repos open as read-vaults (`.obsidian/` gitignored since #62), and the v5 `.claude/`
home doubles as a mini-vault of the harness's knowledge.

**Boundaries:** write-only stays (no vault → SENSE read path); no new pack keys (reuse
`capture.vault_sink_*`, neutral default OFF); Lintel never reorganizes the vault and never
duplicates the vault's own synthesis automation (weekly-review et al.).

## Consequences

- The operator's existing vault skills can query Lintel notes mechanically (typed properties).
- A second repo joining the vault gets its own hub + shows up in the same dashboard — the
  graph view of Lintel-connected repos the operator asked for, with zero graph-specific code.
- `li-vault-init` is the only setup step; everything else happens at CAPTURE time.
- If Bases syntax drifts (young feature), only `templates/obsidian/sessions.base` needs a fix;
  the schema contract is independent of it.
- Revisit the read path only with evidence it pays (token cost vs. operator pasting).
