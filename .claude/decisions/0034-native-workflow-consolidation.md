# ADR-0034: Capability-preserving native workflow consolidation

**Status:** Accepted direction within the authorized 2026-09-25 cleanup.
**Authority:** the operator's implementation release, reconciled by the parent execution contract.
**Implementation and acceptance:** `.claude/plans/legacy-cleanup/work.json`.
**Related:** ADR-0011, ADR-0026 through ADR-0033.

## Context

Duplicate command families and inherited routing obscured the native methods.
The historical audit predates substantive browser, document, context, installation
and evidence work. Replaying its deletion/count targets would discard working value.
The accepted solution must reduce duplicate entrypoints without weakening those
contracts or claiming historical observations as current clearance.

## Decision

Consolidate intake into DEFINE; plan and repository inspection into `inspect` with
explicit lenses; read-only verification and authorized repair into `verify`; owned
investigation into `diagnose`; actual independent review selection into `cross-check`.
Retain generic `review`, `ship`, `code-freeze`, `perfbench`, the nine cycle phases,
engineering modules, legitimate vendor support and useful agent roles.

Use `pause`, compatible `resume`, bounded `context-warm` modes, `lessons-add`,
`lessons-surface` and `skill-new` for continuity. Preserve saved data, old filenames,
operator preferences, job-step resume and selected-work precedence. Freeze/list/lift
share the existing advisory state grammar between the method and optional hook.

Use `web-session` modes over the existing provider and resources. Fold advice,
variants and built-UI review into the existing frontend owners; put mockup rendering
in `generate-web`, source-grounded documentation in `generate-docs`, and direct PDF
print options in `generate-pdf`. Keep the PDF writer and workbook capability.
ADR-0033's reader removal and unverified PDF inspection boundary remain authoritative.

Duplicate cycle compositions become explicit cycle ranges. CAPTURE/SHIP retain release
summary and retrospective methods; doctor retains actual installed-health checks;
catalog/welcome retain discovery. Preserve the real conversational audience method
under `role --audience`, separate from persistent role/profile changes.

Retire expired public alias records with surgical in-place registry edits. Native
installation still uses its owned receipts/inventory and no Python prerequisite.
Repository adapters use their existing source bundle and transaction engine; update
their actual dependency closure rather than adding another installer inventory.

## Evidence, authority and provenance

Review/QA remains the existing v2 content/attempt/work/profile-bound contract with
latest-decision semantics and independent corroboration. No regex/heading clearance,
new schema or role-play independence substitutes for it. Context and native-path
ownership remain unchanged.

Keep required notices and exact historical inputs where necessary to represent the
original observation. Not every narrative review is cryptographically bound. Record
each residual by exact path/field and rationale, distinguish current routing from
original observations/citations, and do not claim repository-wide zero tokens.
Parent-reserved presentation publication and the separately owned upstream record
follow-up remain outside this change.

## Alternatives

1. Delete whole historical families to hit a numerical target. Rejected: working
   providers, readers of persisted data and document capabilities would be lost.
2. Keep every alias and wrapper indefinitely. Rejected: duplicate authority and
   stale routing would remain the default operator experience.
3. Selected: consolidate public methods, retain actual capabilities/data and shared
   contracts, update all real consumers, and verify the integrated result.

## Verification and migration

Use six disjoint, attributable implementation lanes and one coordinator. Reconcile
the released main base, integrate serially, regenerate only from current sources,
and obtain specification then separate quality review of the actual aggregate.
Source-only or synthetic checks do not imply browser/application/native artifacts.
Required strict hosted checks remain required even when an upstream delivery used
different rush authority.

Publish a fresh consistent product version after final-main reconciliation.
Document each replacement and re-run the existing owned installer/adapter update
for installed consumers. Unknown files/edits, old checkpoints, receipts and historical
logs are preserved. Rollback is a separately reviewed forward change or ordinary
revert, not a history rewrite or deletion of user data.
