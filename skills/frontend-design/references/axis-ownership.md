# Frontend axis ownership

Each axis has one decision method and one publication owner:

| Axis | Decision method | Admission and publication |
|---|---|---|
| Typography | TypographyCurator | `frontend-typography` and shared `design_contract.emit_fragment` |
| Motion | MotionDirector | `frontend-motion` and the same shared emitter |
| Shader | ShaderEngineer | `frontend-shader` and the same shared emitter |

Use the named method in the current context unless separate expertise/context
is useful and actually available. Delegation is not automatic and the role name
does not prove a tool was invoked. A requested independent review remains a
separate obligation; doing the same method twice is not independence.

## Decision result, not a second writer

The role returns a draft fragment and its reasoning, inputs and limitations.
The calling skill owns input/profile admission, the explicit output destination,
the single emitter call and readback. Do not let both role and caller overwrite
the output or re-enter each other's dispatch step.

Keep the existing fragment schema and validated no-motion/CSS/no-shader branches.
The shared [design contract](../../design-dna/references/design-contract.md)
owns field validation, provenance and required evidence. Role examples and vendor
lists are candidates, not defaults, current release facts or permission to install.

Use the actual brief, verified profile, corpus evidence and installed project.
Preserve a suitable existing choice. Ask only for a missing decision that changes
the outcome; do not force a font, animation, shader or extra context.

## Actual asset observations

These roles do not declare a web-fetch tool. Use supplied or already verified
release/license evidence, or hand the exact missing check to an available,
authorized lookup. Never claim that current terms or device behavior were checked
merely because a candidate was named.

Use the existing [selected asset evidence](../../design-dna/references/design-contract.md#selected-asset-evidence)
procedure. A mandatory unresolved obligation blocks the affected publication;
an advisory unknown stays explicit in the draft. No role may grant a license,
invent a performance measurement or treat its declared tools as host enforcement.
