Prompt · Product brief · Runtime v2 · Public provenance

The product brief is preserved verbatim. Its older server-start and free-technology paragraphs are superseded by the shared v2 runtime contract; read them together.

The controller owns the clock.

  1. The controller serves public/ and /fixture.json. Candidates build vanilla HTML, CSS and JavaScript modules; they do not start another server.
  2. The first matching native user-message timestamp starts the window. Planning, implementation and required review all count.
  3. When the work and required reviews are finished, the candidate runs node BENCHMARK-SUBMIT.mjs once and stops all writers.
  4. The controller grades an immutable allowlisted snapshot, checking its content hashes before and after grading.

A ready marker is a declaration, not a passing result. A timeout remains a timeout. Later snapshots are diagnostic and cannot recover the original completion time.

Normal host permissions remain unchanged. The benchmark does not install command-intercepting hooks or create an operating-system sandbox. Unexpected permission or transport faults remain visible infrastructure failures.

32 requirements. 100 possible points.

Try one boundary: two soups and a lemonade with KITCHEN10 must total $21.29. Then cancel an order twice: stock must be restored exactly once. Reload: a completed checkout must not happen again.

K16 and K25 weigh five points; the other requirements weigh three. These targeted checks do not certify complete security or accessibility.

A fair test can disappoint you.

  • Freeze the prompt, runtime, starter, fixtures, grader, selected Lintel revision, models, permissions and limits before a cohort.
  • Keep graders, reference solutions, coordinating transcripts and previous results outside candidate context. Inspect actual host discovery; a fresh folder alone does not remove global instructions.
  • Run arms sequentially. Counterbalance their order over repeated independent cohorts. Overlapping uncontrolled activities are not a fair timing comparison.
  • Naked versus Lintel changes the workflow and delegate-model configuration. The two Lintel arms keep the same delegate models and review policy. A separate all-same-model series controls the model mix further.
  • Record actual active implementation overlap to establish swarming. Session lifetimes alone do not establish it.
  • Retain failures, exclusions and every grading attempt. Do not repair a candidate after its stop boundary and retain the earlier completion time.
