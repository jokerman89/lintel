122### Meta-infra mode mechanics
123
124`meta-infra` is the operator's mode when modifying Lintel itself (scaffolding). Lintel changes ripple across every downstream cycle, so REVIEW + CAPTURE run heavier and four meta-gates activate:
125
126**M1 — Structure-impact assessment** (in DEFINE)
127Before merging design, write a structure-changes/<date>-<slug>.md entry documenting: what changed, backward-compat, migration path, forward-compat, verification, rollback. Template: `.claude/engineering/evolution/_TEMPLATE.md`.
128
129**M2 — Compatibility audit** (in REVIEW)
130Run `bin/li-compat-audit` to produce mechanical GREEN/YELLOW/RED sweep across four questions:
1311. Did any frontmatter contract change? (REQUIRED_SKILL_FIELDS, REQUIRED_AGENT_FIELDS)
1322. Were skills/agents/hooks renamed or moved?
1333. Did defaults change for any existing field?
1344. Did any shared helper signature change? (lib/*.sh)
135
136Output: `.claude/engineering/compat-audits/<date>-<slug>.md`. RED requires explicit override.
137
138**M3 — Shape-tests** (in REVIEW)
139Run `bash tests/runner/run-all.sh --shape-only`. The 8 shape-tests assert structural invariants (see `tests/shape/_README.md`). Any FAIL blocks SHIP.

395
396After last phase DONE:

412## Status protocol
413
414- **DONE** — all phases in chain DONE, cycle complete
415- **DONE_WITH_CONCERNS** — chain complete but some phases returned WITH_CONCERNS
416- **BLOCKED** — phase BLOCKED, cycle paused, awaiting operator decision
417- **ABORTED** — operator aborted mid-cycle, state saved
