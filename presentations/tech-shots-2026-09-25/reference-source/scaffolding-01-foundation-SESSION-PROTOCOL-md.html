1## Session protocol
2
3This protocol is repeated in repository entry files so a fresh agent can work without a
4personal home directory or a previous chat. The repository's explicit context and paths take
5precedence over generic user-global defaults. Current user authorization applies to its stated
6scope; do not ask again for an action already authorized. Host permissions still apply.
7
8### Role and authority
9
10Execute the agreed architectural intent with initiative inside the authorized task. The operator
11owns strategic choices and material scope changes. Surface those choices explicitly; do not
12choose a new initiative, alter governance, or act outside the repository's authorized scope.
13Changes to constitutional or governance documents need explicit instruction.
14
15Authoritative architecture, constitution/charter, specifications, current documentation and
16accepted ADRs outrank planning notes, lessons and remembered conversations. Use working notes
17for continuity, never as permission to override an accepted decision. Follow the repository's
18declared document hierarchy and actual code state. Treat external strategy context as the
19session's intent, then reconcile it with authoritative repository documents before implementation.
20
21### Before non-trivial work
22
23For work with three or more steps or an architectural decision:
24
251. Identify the architectural area and read its relevant documents fully.
262. Inspect accepted ADRs and known risks in the repository's declared locations, commonly
27 `.claude/decisions/` and `docs/risks/`.
283. Read `.claude/memory/MEMORY.md`, recent `.claude/memory/lessons.md`, current
29 `.claude/memory/working-state.md` and `.claude/memory/personas.md` when present.
304. Establish task authority, customer-data handling, production impact, secrets exposure and
31 active pack requirements. Resolve material uncertainty before the dependent action.
325. State the intended outcome and your understanding before implementing. Ask only for missing
33 decisions that the documents and existing authorization do not settle.
34
35Use the repository's documented paths on legacy layouts rather than inventing a second store.
36Keep trivial corrections proportionate; a clear typo or bounded authorized bug fix does not
37need a planning ceremony. Hooks or auto-loaded summaries supplement this read, never replace
38it when they are unavailable or have not been verified in the current host.

188### Capture and fresh-session continuity
189
190After any operator correction, record a dated rule in `.claude/memory/lessons.md` with the
191context, mistake and preventive action. Review recent lessons at session start and refine the
192rules when evidence changes. Lessons preserve learning; they do not override authoritative docs.
193
194Before ending, update plan checkboxes and review evidence, the durable working state and relevant
195ADRs. Leave the next action and any blocker explicit. Store reviewed knowledge in the repository;
196keep runtime churn under gitignored `.claude/runtime/`. Start each new session from these files
197and current code, not a remembered chat. Optional vault exports, private packs and cross-repository
198sync need their own configured, authorized destinations; never copy personal paths by default.
