89### Step 2 — Lessons capture (filtered)
90
91Invoke `/li:learn` (or inline):
92
93For each correction operator made during the cycle:
94- Was this correction GENERAL (would apply to future work) or SPECIFIC (one-time)?
95- If GENERAL: candidate for `.claude/memory/lessons.md`
96- If SPECIFIC: keep in this cycle's notes only
97
98Examples of LESSON-worthy:
99- "Don't mock the vendor SDK in tests — last 3 cycles' tests passed but prod failed because mocks diverged from real API"
100- "Always map the codebase first when planning infra work — saved 90 min on this engagement"
101
102Examples NOT lesson-worthy:
103- "Use specific port 8443 in this customer's deployment" — too specific
104- "Forgot to update README" — operational, not a pattern

106**Update-phase (ADR-0006) — classify BEFORE appending.** Append-only capture is the documented
107failure mode of file-based memory. For each candidate, grep what already exists:
108
109```bash
110source "${LINTEL_SOURCE_ROOT:-$LINTEL_REPO_ROOT}/lib/memory.sh"
111lessons_find_related <candidate keywords> # all related active lessons, ranked
112```
113
114Classify against the hits:
115- **add** — nothing related exists → new `## L-NNN — <title>` entry
116- **update** — an existing lesson covers it but the candidate sharpens it → extend THAT lesson's
117 How-to-apply (note the cycle id), no new entry
118- **supersede** — the candidate CONTRADICTS an existing lesson → write the new entry, then add
119 `superseded_by: L-<new> (<date>)` as the first body line of the old one. Never delete or edit
120 the old lesson away — git holds ingestion history, the marker holds validity
121 (supersede-don't-delete).
122- **no-op** — an existing lesson already says this → skip, mention the existing id
123
124AskUserQuestion per candidate lesson: "Capture as <classification>? (yes / no / edit-first)"
125
126If add: append to `.claude/memory/lessons.md`:
127```markdown
128## L-NNN — <lesson title>
129<lesson body: Rule / Why / How to apply>
130<-- Captured from cycle <cycle-id> by <operator>. -->
131```

210### Step 6a — Reaffirm swarm evidence and future-operator clarity
211
212When the selected work map opts into swarming, resolve helpers only from explicit
213`LINTEL_SOURCE_ROOT`, then Claude's `CLAUDE_PLUGIN_ROOT`; other adapters export their known installed
214bundle. Without either trusted root return `NEEDS_CONTEXT`. Run `li-work-artifacts.py` and
215`li-swarm.py verify` with the working repo only as `--repo`. Tests/self-checks export
216`LINTEL_SOURCE_ROOT` explicitly. Preserve the work map, charter, briefs, worker reports, and
217independent reviews with the trio; they are the cold-resume evidence for topology and ownership.
218Do not copy task text, dependencies, status, or acceptance into coordination.
219
220Only the coordinator may set the work-map status to `COMPLETE`, and only after all lane evidence,
221serial integration, final integrated REVIEW, and SHIP evidence pass. Local runtime attempt files and
222abandoned worktrees are not durable completion evidence.
223
224For meta-infra M4, the future-operator recap must name:
225
226- the explicit opt-in fields and coordination path;
227- the actual host tier used (`native`, `sequenced`, or `none`) and whether writers really ran
228 concurrently;
229- the isolation/attribution method and deterministic integration order;
230- lane reports/reviews plus final integrated review evidence;
231- any lost attempts, sequenced fallback, migration, deprecation, or unverified host behavior.
232
233Never claim independent review when the same identity implemented and reviewed a lane. Honest
234degradation is part of the durable outcome, not a concern to hide.

244### Step 7b — Vault sink (session summary → knowledge vault)
245
246Config-gated, optional, NEVER blocking. Writes a short human-readable session summary to an
247external knowledge vault (e.g. an Obsidian vault) so the vault becomes the cross-repo memory
248layer. The repo's own capture artifacts (Steps 1–7) are unaffected — this is an additional
249sink, not a move. Nothing is ever read back from the vault into the repo.
250
251```bash
252source "${LINTEL_SOURCE_ROOT:-$LINTEL_REPO_ROOT}/lib/pack-resolver.sh"
253sink_enabled=$(resolve_pack_field capture.vault_sink_enabled)
254sink_path=$(resolve_pack_field capture.vault_sink_path) # relative to repo root
255
256if [ "$sink_enabled" != "true" ]; then
257 : # disabled — skip silently
258elif { case "$sink_path" in /*|[A-Za-z]:*) sink_dir="$sink_path" ;; *) sink_dir="$REPO_ROOT/$sink_path" ;; esac; [ ! -d "$sink_dir" ]; }; then
259 echo "[lintel/capture] WARN: vault_sink path not found: $sink_path — skipping vault export"
260 audit_log capture vault_sink_skipped "reason=path_missing" "path=$sink_path"
261fi
262# A missing or disabled vault must NEVER fail CAPTURE — one-line warn, then move on.
263```
264
265When enabled and the path exists, write exactly ONE file per session,
266`<sink_path>/YYYY-MM-DD-<repo>-<short-slug>.md`:
267
268```markdown
269---
270created: YYYY-MM-DD
271tags: [session]
272type: session
273repo: <repo-name>
274branch: <git-branch>
275outcome: shipped | in-progress | blocked | exploration
276session: <cycle-id-if-available>
277---
278# <one-line session title>
279
280## What was done
281<3–8 lines, plain language, no code dumps>
282
283## Decisions
284<decisions taken, one line each; "None" if none>
285
286## Open threads
287<unfinished items / next steps; "None" if none>
288
289## Pointers
290- <repo-relative paths to the key files/PRs touched>
291
292## Links
293- [[<repo-name>]] <- the repo hub note (backlinks = per-repo session history)
294- [[<previous session note name>]] <- predecessor, if one exists for this repo
295```
296
297The frontmatter is a LOCKED flat schema (ADR-0007) — `sessions.base` (the Bases dashboard
298installed by `bin/li-vault-init`) and the vault's own skills query these exact properties.
299`outcome` uses the controlled vocabulary above, nothing else.
300
301**After writing the note, maintain the two navigation surfaces (same sink dir):**
3021. **Hub note** `<sink_path>/<repo-name>.md` — create a minimal one if missing (frontmatter:
303 `created:`, `tags: [hub]`, `type: repo-hub`, `repo:`; one line of prose — same shape
304 bin/li-vault-init writes). Never overwrite an existing hub.
3052. **Index** `<sink_path>/00-index.md` — create it if missing (frontmatter `type: session-index`
306 + one intro line), then maintain the list under its heading: carry the existing entries
307 forward, PREPEND this session's line, truncate to 15:
308 `- [[<note-name>]] - <one-line title> (<repo>)`. Keep frontmatter + intro intact; touch only
309 the list. (Carrying forward the index's own lines is the one sanctioned vault read — never
310 read other notes back.)
311
312Source the content from the Step 1 cycle aggregation. **Hard rules:** no secrets or tokens, no
313customer or employer-internal data, no full file contents — repo-relative pointers instead of
314payloads. Render the headings AND body in the session's working language (the template above is
315the canonical English form — translate it wholesale when the session ran in another language).
316Frontmatter must parse.
317
318**MANDATORY pre-write scan (battletest K4 — the vault note lands OUTSIDE the repo, where no
319git-commit hook sees it).** The "hard rules" above are not enough on their own — scan the
320rendered note body programmatically before writing, and ABORT the export (warn, never fail
321CAPTURE) on any hit:
322
323```bash
324source "$LINTEL_REPO_ROOT/hooks/shared/_patterns.sh"
325note_body="$(cat "$rendered_note")"
326sec_hits="$(scan_secrets all "$note_body")"
327pii_hits="$(scan_customer "$note_body")"
328if [ -n "$sec_hits$pii_hits" ]; then
329 echo "[lintel/capture] WARN: vault export ABORTED — ${sec_hits:+secrets: $sec_hits }${pii_hits:+pii: $pii_hits}"
330 audit_log capture vault_sink_skipped "reason=sensitive_content" "secrets=$sec_hits" "pii=$pii_hits"
331 # skip the write entirely — do NOT sanitize-and-ship; an aborted export is correct
332else
333 # write the note, then:
334 audit_log capture vault_sink_written "file=<filename>"
335fi
336```
