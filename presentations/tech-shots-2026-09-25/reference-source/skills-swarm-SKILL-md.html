27You are the SWARM skill — the opt-in execution profile over PLAN, BUILD, and REVIEW.

29## What this skill does
30
31Coordinates dependency-ready work without becoming a scheduler or a tenth cycle phase. The mapped
32`tasks` artifact remains the only authority for card text, dependencies, status, and acceptance.
33The coordination document adds execution topology only: waves, roles, write scopes, isolation, and
34brief/report/review pointers.
35
36`bin/li-swarm.py` is the read-only mechanical gate. It validates artifacts, calculates the next
37evidence/topology candidate frontier, checks one attributable lane change set, reports status, and
38verifies close evidence. It does not parse or decide authoritative task dependencies. The
39coordinator still reads those prerequisites from the mapped task card, selects host tools, spawns
40agents, integrates changes, writes shared state, commits, and makes operator-facing decisions.
41
42## When to use
43
44- An approved plan has two or more dependency-independent domains.
45- Ownership can be expressed as disjoint repository-relative scopes.
46- The operator explicitly opts in through PLAN or invokes `/li:swarm`.
47- A fresh session needs to inspect or resume a committed swarm.

150### `/li:swarm resume <coordination-path>`
151
152Revalidate the committed map and coordination file, inspect status, and calculate `wave` again.
153Treat missing runtime attempts as lost attempts, not completed work. Preserve any attributable
154worktree/patch, check its scope, and either finish its report/review or re-dispatch the same brief.
155If attribution is unavailable, discard no work silently: surface the discrepancy and sequence a
156new attempt. Resume never chooses a different initiative by recency.
157

1633. Run focused integration checks, then hand the reconciled branch to the ordinary REVIEW phase.
1644. REVIEW reruns specification, quality, and compliance across the full integrated diff. Lane
165 reviews do not replace this final gate.

197## Anti-patterns
198
199- Duplicating card text, dependencies, acceptance, or status into coordination metadata.
200- Dispatching work from chat or `wave` alone instead of reconciling its candidate frontier with the
201 mapped card's authoritative prerequisites and completion evidence.
202- Concurrent writers in one shared tree with only a union diff as evidence.
203- Letting a worker edit its review, shared state, generated reducers, commits, or integration branch.
204- Calling lane review a substitute for final integrated REVIEW.
205- Claiming concurrency or independent review on a host that did not produce that evidence.
206
207## Failure recovery
208
209Validation failure returns to PLAN. A worker scope breach quarantines that attributable change set
210until the coordinator narrows scope, serializes it, or re-runs the lane. A failed lane review returns
211to the same task and blocks later waves. Lost runtime state is reconstructed from committed artifacts,
212Git, reports, and reviews. External mutations still require their normal authority; swarm opt-in does
213not expand it.
