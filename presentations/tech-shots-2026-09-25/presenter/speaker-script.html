You do not need to learn nine names. Learn the shape.

Reference for questions: Lintel’s own documentation says it directly — the expensive failures in agent-driven work are correct code built against the wrong premise, discovered three hours later. SENSE reads the situation and ends with a suggested route, which is the next screen. SCOPE sizes the request and asks at most one question. DEFINE produces an approved design, not a draft. DISCOVER only reads: existing decisions, lessons and patterns. PLAN writes three files together: checkable tasks, what done means, and a brief for a fresh session. REVIEW is deliberately adversarial: spec, quality, team standards. SHIP opens a pull request by default. CAPTURE keeps lessons, a decision record and the working notes the next session picks up — the handoff — which a later DISCOVER can find; that is why it is a cycle. Every “skip it and” line is that step’s own declared cost from the documentation, not a measurement.

Claim boundaries: “at least twice” is deliberate. On a full run you are asked to confirm the route after SENSE, possibly one sizing question, then the design, the plan, and an estimate shown before BUILD — a task count and a token estimate labelled uncalibrated, never money or time. An approval gives you the chance to catch a wrong premise; it does not catch it for you. These are instructions the agent is told to follow; real enforcement is the platform’s, which is why there is no lock on this screen. “Leaves something written” does not mean committed: the situation report and the sized request are temporary working state, and a later screen draws that line. Swarming is an optional way to run PLAN, BUILD and REVIEW, not a tenth step. The strip is the illustrative opening conversation, not a measured run.
