02:30–04:00 · SLIDE 42

Clear ownership. Independent challenge.

SAY A role carries expertise. Independent review needs a separate, attributable reviewer.

DO Follow preparation, implementation and challenge. Separate the MARS review panel from the Swarm implementation diagram.

THEN All of that work needs a place to leave its evidence.

One implementer owns a bounded package. Reviews cover every original leaf and their integration. Substantive work needs actual independent review; a role name, another model name or a builder's self-review cannot manufacture it. Mechanical work can use the documented coordinator review.

The shared Review Method gives single REVIEW and each MARS participant the same frozen packet body: acceptance, standing questions, evidence levels, severity and coverage. MARS is an optional multi-model second look with consent and observed host capability. Reviewers work blind first; at most one challenge round follows contested claims. The coordinator judges source evidence rather than voting and preserves dissent. MARS itself never grants release clearance.

Swarm is different: it schedules implementation packages. One coordinator owns shared state and integration. Concurrent writers need disjoint scopes and attributable worktrees, patches or equivalent isolation. Without that, replay the briefs serially. Lane reviews never replace the final integrated review.

06:00–08:00 · SLIDE 44

Each phase leaves a usable record.

SAY The record carries the selected work and its evidence into the next phase.

DO Start at PLAN. Select BUILD, REVIEW and CAPTURE. Use other tabs only if asked about paths.

THEN The same records let a fresh session find the unfinished step.

Start an explicit cycle identity and verified profile context before phase writes. The ledger carries the original map, artifact paths and policy reference. The work map indexes authority; it is not a duplicate backlog. Spec Kit keeps its original task IDs and files.

BUILD records evidence per leaf and reviews each bounded package for spec compliance and then quality. One failed leaf keeps the package open and preserves useful completed evidence. BLOCKED returns to BUILD with the exact unresolved action.

REVIEW sends the shared method packet and checks coverage, then persists content-bound v2 decisions and immutable QA obligations. A later rejecting or malformed applicable decision blocks an older pass. Missing mandatory validation or independent corroboration stays open. A complete report can still contain a failing verdict; a checker exit code alone is not a PASS.

SHIP consumes current review and QA within existing authority. CAPTURE reaffirms actual outcomes and records warranted lessons or decisions. It cannot approve missing work or authorize a deployment.

08:00–09:30 · SLIDE 45

Resume the work. Keep its identity.

SAY Pause saves continuity. Resume reads it alongside the original work and current evidence.

DO Point to the committed map, then the original artifacts. Name the missing-review boundary.

THEN Continuity helps; the actual client still decides which controls can run.

Use pause to reserve a collision-safe, owned checkpoint. The compatible filename still ends in -context-save.md; old saved data is not renamed or deleted. Verify nonempty readback before claiming it was saved. resume --from <checkpoint> reads continuity context; it does not restore code, change branches or grant BUILD or SHIP authority. A bare phase or selected job-step keeps the existing override meaning; use an explicit path such as ./BUILD if a checkpoint name collides.

Explicitly selected work wins over an unrelated local ledger or checkpoint. A fresh clone follows an unambiguous committed work map and its original artifacts, then reconciles actual checkout and acceptance evidence. It does not choose the newest file or fabricate lost evidence.

Resume verifies the original cycle, target and profile generation/digest. Missing or changed policy needs explicit reconciliation. STARTING, BLOCKED and NEEDS_CONTEXT return to the same unfinished phase. A truncated DONE cannot advance.

13:30–14:30 · SLIDE 48

Carry the policy with the work.

SAY Preferences choose context. Required policy must stay intact from plan through delivery.

DO Move require → resolve → verify. Point to platform permissions and CI as separately configured controls.

THEN Then preserve what the next task can actually use.

profile.yaml holds operator preferences such as role and mode. Required repository or explicit pack selection is different. The effective context binds actual source content, target, generation and digest. A pack name alone cannot establish that the same policy was applied.

Carry the verified reference through selected work, children, review, QA and recovery. Missing required packs or changed policy do not silently fall back to neutral success. A deliberate switch/rebind records a reason, retains prior history and requires affected work to be reconsidered.

Packs provide reviewed standards and context. Platform permissions, CI and live organizational enforcement remain their own configured and verified layer. Required-policy source tests are not an enterprise certification.

14:30–16:00 · SLIDE 49

Keep useful knowledge. Preserve the evidence.

SAY A lesson helps only when later work retrieves and applies it.

DO Walk capture, retrieve and preserve. Distinguish checkpoint continuity from owned-file recovery.

THEN The pilot should verify this whole path, including failures.

lessons-add checks existing entries before choosing add, update, supersede or no-op. Stable L-NNN IDs, a lock and a conditional write preserve ownership and history. There is no active operator-global lessons sink; old global JSONL is read-only legacy data. lessons-surface ranks active literal-keyword matches, then the agent reads and applies the full rule. Stored text or a ranked heading alone does not prove better outcomes.

ADRs record consequential choices and rationale, normally beginning Proposed. CAPTURE reaffirms the original mapped task outcomes and handoff rather than generating a competing backlog. Standalone retrospective and release-summary modes preserve their selected window and publication boundary.

Owned snapshots protect recent copies, the newest five and incomplete operations. Pruning needs explicit eligible IDs and refuses unexpected content. Keep transaction receipts with their snapshots. This is bounded recovery, not a universal cleanup policy or a way to compact a model conversation.

Negative cases matter: changed policy, skipped mandatory QA, missing independent reviewer, later rejecting decision, ambiguous work map and edited managed files. For MARS, a changed brief, substituted model or incomplete panel must remain visible. For Swarm, missing attribution means serial work and missing review leaves the lane open.
