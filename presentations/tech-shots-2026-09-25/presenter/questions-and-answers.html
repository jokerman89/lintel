LINTEL / PRESENTER GUIDE

Questions worth answering

Why use a harness when models keep improving?

A stronger model reduces the value of generic expert-role instructions. It does not make unavailable project decisions available. The stronger hypothesis is curated project knowledge, cross-session continuity, a shared method across tools and checks that catch real faults.

Is Lintel replacing native skills, agents or project instructions?

No. Those are useful building blocks. Lintel must earn its place through the content of its workflows, how they fit together and observed outcomes. Merely having the same features is not differentiation.

Did the comparison prove a productivity gain?

No. It is one recorded pair with the same competent repo foundation. It supports specific observations about these outputs and their decision trails. It does not establish causal superiority, elapsed-time savings, cost reduction or generalization across models. Additional method context and stochastic generation remain confounders.

Why does the stronger baseline matter?

A customer already using clear project instructions, tests and CI should compare against that setup. Comparing only against a vague prompt could award Lintel credit for practices the customer already has. The protocol records the restart after strengthening both starters.

What if both implementations pass?

That is useful. Inspect recovery, traceability and maintenance cost. If the extra method adds no useful difference, keep the simpler approach. Do not score document volume as quality.

Does Lintel guarantee quality or security?

No blanket guarantee. Specific executed checks can establish a specific property for the tested inputs. Platform permissions and deployment controls must be configured independently. The existing Claude Code hook bundle is not automatically enforced by another host.

Does every task need all nine phases?

No. Start with the smallest useful core. Add deeper planning or review when risk, ambiguity or coordination justify it. ADR-0009 supports reducing repeated ceremony; ADR-0021 describes evaluation needs. Accepted direction is not the same as implemented capability.

How do I ask for a shorter route?

Run the cycle with your request: SENSE recommends a route and you confirm it with Proceed? [Y/n/edit]. To skip the suggestion, name the mode (hotfix, research-dive); a mode you name always wins. You can also enter at a step, stop early or drop one. The GitHub Copilot kit runs the same cycle, spells skills with a dash, and has no separate fix shortcut. Exact spellings: field guide.

Does SENSE always pick the right route?

No. Today it is first-match keyword rules, and “confidence high” only means a word matched. “Correct the typo…” matches nothing and falls to the full cycle; “Add error handling” routes as a fix because “error” is tested first. That is why the route is a recommendation you confirm. The four requests on screen were checked against the real rules: source manifest.

What if it sends a big job down a short path?

Where SCOPE runs, a request that could be small or large gets exactly one question, is treated as large until you answer, and is re-routed to the full cycle only if the large reading stands and nothing is built yet. SCOPE does not run on hotfix or research-dive; there the confirm prompt is the only net.

Does a hotfix skip review, or never record a lesson?

It keeps REVIEW and SHIP. It skips SCOPE, DEFINE, DISCOVER, PLAN and CAPTURE. Any single phase can be run on its own afterwards, so a lesson can still be captured.

You say depth follows risk. The routes screen says depth follows a keyword.

The principle is risk. Today’s implementation is a keyword guess plus your judgement at the confirm prompt: the same button change phrased without “fix” gets the full cycle. That gap is stated on the screen, and it is why the human confirm is drawn on the line.

Can customers new to Copilot benefit?

Potentially: make a repeatable workflow and its questions visible, then verify one useful slice. Use synthetic or authorized data and the customer’s controls. Evaluate a bounded pilot rather than promise faster delivery from this demo.

Is compounding context model training?

No. It is reviewed, persistent material retrieved when relevant: decisions, lessons, workflow instructions and evidence. Tests provide a different kind of memory by rechecking behavior.

Does universal mean identical behavior in every client?

No. The shared method is portable; discovery, hooks, delegation and permissions differ. Validate the installed adapter and capabilities in the actual host.

Where do MDASH and AGT fit?

They address different needs. This talk does not assert a feature mapping or competitive comparison without their source material. Its focus is the development working method around what, how, why and continuity.

What lives globally, and what travels with the project?

The operator profile and installed packs live in the machine-global Lintel home, ~/.lintel/. Coding-client settings and permissions remain host-owned. Reviewed plans, decisions, lessons and handoffs live in the project’s declared storage and can be committed with Git. Temporary .claude/runtime/ execution state is ignored. The .claude folder name does not require Claude Code. A clone does not install your global profile or packs on another machine; configure those separately. See the storage guide for the exact paths and Copilot adapter layout.
