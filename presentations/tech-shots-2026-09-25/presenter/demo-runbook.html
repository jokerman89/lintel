Run the kitchen demonstration

The presentation now uses the three-arm Service House kitchen test. The previous two support dashboards are retired from the current public exhibit.

Before presenting

  1. Read the kitchen harness README and RUNBOOK. Pin the finalized accepted Lintel source and exact host configuration. Do not begin measured model builds until the operator authorizes them.
  2. Rehearse the harness mechanics: npm test, npm run verify, then npm run demo. Reference/control grades are not candidate results.
  3. When authorized, prepare fresh isolated candidates, inspect real host discovery, calibrate the naked task, then run the three treatments sequentially. Keep the brief and grader frozen.
  4. Import actual complete session billing and active-execution evidence. Never replace unknown cost with zero or session lifetime overlap with proof of swarming.
  5. Keep each candidate website running for the talk after its model sessions are stopped. Preserve the frozen results. Rehearse the same clicks in all arms.

TV-chef delivery

The builds happen before the session. Inspection happens together. Show the exact common brief, then the real candidates and their failures. Use the local dashboard; the public Pages guide is a protocol and handout, not a server replacement.

When results are not ready

Say: “The comparison is pending. Here is what we will measure.” Open the public kitchen guide, show the32 requirements and trace one contract. Never use the reference app as an arm, reuse old 14/14 results, invent a winning plan or improvise billing.

What stays separate
