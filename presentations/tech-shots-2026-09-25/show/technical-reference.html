Shared execution and storage contract

Runtime. These are Bash scripts, not portable POSIX sh despite README wording. Common dependencies are Bash, git, grep, sed, awk, find, date/stat and filesystem access. Some need additional tools. _input.sh:20 reads stdin with a bounded timeout; _input.sh:56 extracts Claude-shaped tool_input fields via jq or a best-effort sed fallback. If input extraction returns empty, many checks simply return success. Most file checks assume cwd is the working repo and receive a suitable relative path; absolute paths can miss relative-path patterns.

Audit output shorthand A. Most firing advisories write category hooks through bin/_audit.sh:134: normally <repo>/.claude/runtime/audit/hooks.jsonl for a v5 marked repo; otherwise $LINTEL_HOME/audit/hooks.jsonl. A non-default explicit LINTEL_AUDIT_DIR overrides routing (bin/_audit.sh:30–82). Job-category logs go to the corresponding jobs.jsonl. Resolver logs remain operator-global; its cache is $LINTEL_HOME/sessions/<session-id>-pack-cache.yaml (lib/pack-resolver.sh:34–42). Many scripts also create the global audit directory even when the eventual record is repo-local. An audit-write failure prints a warning rather than blocking (bin/_audit.sh:170). Most scripts log only a match, not every invocation; context-bloat intentionally does not audit.

Warning semantics. Plain stdout + exit 0 means the script emitted advice; it does not prove the user/model saw it. No live client output-channel validation was run here. “Warn-only” scripts generally use set -euo pipefail; missing tools, parsing failures or unmatched pipelines can produce early nonzero exit before the warning. That is not intentional security blocking. The architecture's intended fail-open behavior is not equivalent to every branch being error-free.

Git blockers. _input.sh:107–127 unions added lines from staged and unstaged tracked diffs for cwd and extracted git -C targets. Push additionally compares upstream..HEAD, falling back to the last 10 commits. It disables textconv/external diff execution. It is a heuristic command/content gate, not a full shell interpreter, exact pushed-ref evaluator or complete secret/DLP product. Diff errors are suppressed; empty scan content permits continuation. Commands containing cd other && git ... are recognized but the helper does not interpret cd to change scan location. Untracked files staged later in a compound command are not present in the current diff.

Pattern specificity. _patterns.sh:26–45 defines 11 strict secret pattern families and two extra warn-only heuristics. Customer scanning has one shared set: email, broad phone, Swedish personal-number pattern, name-plus-case-ID (:49–57). It cannot distinguish real customer data from public addresses/test fixtures. Both blockers permit environment/leading-command overrides and default missing reason to no-reason-given; they do not authenticate the origin of the override (secret-scan-block:45, customer-data-block:35).

Findings that change presentation claims

These are source-observed limitations or explicitly labeled inferences; this pass is not a full runtime/security audit.

  1. Activation is part of the feature. Show nine configured core scripts, not33 universally running safeguards. Optional event labels do not demonstrate registration. Job helpers need workflow arguments and remain dormant by decision.
  2. A hook can inspect, remind, deny or write. These are different behaviors. Jobs have write/archive/delete side effects; calling everything a warning or all hooks “read-only” is wrong.
  3. Most optional file analyzers run too early to assess the change they describe. Their docs suggest PreToolUse but code reads the existing file and often skips missing files. Reframe them as context/advisory prototypes until a prospective-payload or post-edit integration is verified. This affects complexity, migration, retention, cost, observability and auth-pattern checks directly.
  4. Mechanism is narrower than the name. Screenshot=DOM scan; cost=pattern reminder; threat coverage=path mention/age; compliance=evidence-file presence/age/text; performance=budget-path reminder; coverage=prior report parse. None proves the wider guarantee by itself.
  5. Missing sources can mean no warning. Token/call telemetry has no executable producer found. ADR watchers miss the canonical directory. Several optional parsing branches can exit on no-match. These features should not be the flagship live proof.
  6. The canonical source is not consistently respected by optional hooks. Several load a repo-root pack helper and parse profile YAML themselves rather than using trusted source/resolved pack data. Do not represent optional modules as uniformly enterprise-ready pack enforcement.
  7. Overrides are logged attempts, not approvals. Blocker override reasons are optional, and environment flags cannot attest that a human approved the action. Audit failures do not prevent continuation. Native permissions/CI remain independent.
  8. Logging has its own data surface. Some warning records include the first120characters of a command and paths. Logs are local diagnostic artifacts, not automatically sanitized customer-safe exports. “Every hook fire is logged” in README is false: ordinary clean passes and context-bloat lack records.
  9. Portable runtime needs qualification. Most core commands are Bash/git tools; optional job-stale uses mapfile. Relative paths, process identities, nested profile parsing and jq-free JSON handling are not universal contracts.
  10. Continuity assists rather than guarantees. Context injection does not force model compliance; Stop warning intentionally does not continue the agent. Current registry omits compact matcher. ADR-0023's historical claim that a vendor event did not exist must not be reused as a current vendor fact; this presentation section describes this repository snapshot only.

Packs
